# UI Shell Guide

## Overview

Trace Atlas's UI is a "Sleeve & Glass" tablet shell. `Tablet.tsx` composes two decorative `SleeveContainer`s flanking a single `ScreenViewport`:

```typescript
<SleeveContainer hasPowerSwitch={true} />
<ScreenViewport isPoweredOn={isPoweredOn} />
<SleeveContainer />
```

- `SleeveContainer` (`src/components/panels/physical/`) is purely decorative housing — a logo mark, and the `PowerRockerSwitch` when `hasPowerSwitch` is set. No interactive UI besides the power switch itself lives here.
- `ScreenViewport` (`src/components/panels/physical/`) is the actual interactive surface. When `isPoweredOn`, it renders `Header`, `WorldView`, `NavPanel`, `NavToggleButton`, and `ContentPane` (all under `src/components/panels/screen/`), in that order. `Header` is a sticky, always-visible bar that absorbed both the old `TransportBar`'s controls and `HubNav`'s tile-navigation buttons (`docs/specs/HEADER_HUB_CONSOLIDATION.md`), then lost its own navigation entirely a second time to the nav tree described below (`docs/specs/NAV_LAYOUT_REWRITE.md` Task 10) and its volume slider to Settings → Volume (Task 12). What's left: a Mute `Toggle`, its own facade text doubling as that row's label (`"Volume/Mute"` unmuted, `"Volume Muted"` muted — a naming leftover from when a volume slider shared the row; Mute stays regardless of which Settings leaf is open, so it never moved), and a status block showing the current Attenuation Style's locale coordinates plus a `HH:MM -XX°C` local-time-plus-decorative-temperature reading (purely cosmetic — no gameplay effect). `Header` has no restart or pause/play controls; BPM lives at Settings → Tempo, not read out here. **Known-stale mechanism, not cleaned up:** `useHeaderRowFit`/the `header--inline` class it drives are still wired up in `Header.tsx` and still measured live, but no CSS rule targets `.header--inline` anymore since an earlier restyle replaced that row-merge approach with hand-authored breakpoints — currently a dead, if harmless, measurement. `RobotList` was removed in Roadmap Phase 2 (Layout) — Phase 8's Robot Selection tile replaces it.

**Guardrail** (see [CLAUDE.md](../CLAUDE.md)): all interactive UI — transport, navigation, controls — lives inside `ScreenViewport` only, never in `SleeveContainer`.

## Console Navigation

**As shipped** (`docs/specs/NAV_LAYOUT_REWRITE.md`, `docs/tasks/NAV_LAYOUT_REWRITE.md` — both read for full design rationale/history; this section describes the result, not the plan). The old flat 3-tile model (`Header`'s `RadioButton` nav group, `src/data/headerNavConfig.ts`) is gone entirely — `headerNavConfig.ts` is deleted, and `Header` carries no navigation at all anymore (see the Overview section above). Navigation is a schema-driven, hand-rolled ARIA tree: `NavTree`/`NavPanel`/`NavToggleButton`/`ContentPane` (`src/components/panels/screen/nav/`, `src/components/panels/screen/console/ContentPane.tsx`, schema in `src/data/navTreeConfig.ts`). `HubNav` (`docs/specs/HEADER_HUB_CONSOLIDATION.md`) and the `ConsoleNavigation` `Tabs.Root` bar before it are both historical — this is the tree model's third replacement in the app's history, not the second.

**Shell composition** (`ScreenViewport.tsx`): `NavPanel` renders `NavTree` inside a shell that's permanently docked on the left on desktop/tablet, and an off-canvas slide-over on mobile (`useCabinetTier`'s existing breakpoint tiers — no new breakpoint invented), animated via a `timelineMap`-registered GSAP timeline (`prefers-reduced-motion` respected). `NavToggleButton` (a hamburger/✕ button) renders only on the mobile tier, reachable regardless of what `ContentPane` shows. Selecting any node closes the mobile panel automatically (never on desktop/tablet, where it's always open). `ContentPane` (repurposed from the old `Console.tsx`, same "render nothing when nothing's selected" contract) is the single area a selection opens into — still delegates to `ConsolePanel`'s `TILE_CONTENT: Record<HubTile, ...>` dispatch internally, keyed on `uiStore.activeHubTile`, plus a Close button that resets the top-level selection back to blank.

**The tree itself** implements the full WAI-ARIA APG Tree View pattern by hand (no Radix primitive covers it): `role="tree"`/`role="treeitem"`, `aria-expanded`, `aria-selected`, roving `tabindex` (one node at `tabindex="0"`, everything else `-1`), Up/Down/Left/Right/Enter/Space keyboard support. Each row (`NavTreeNode.tsx`) has two independent controls — clicking the name **selects** it; clicking a separate `+`/`−` button (rendered only when the node has children) **toggles expansion only**, `stopPropagation`'d so it never also selects. Selection and expansion are fully decoupled state: you can peek open a branch without navigating into it, and selecting a node doesn't force its parent open or closed. Expansion is "accordion-of-one" *per level* — expanding one node collapses its previously-expanded sibling at that same level, tracked by a small set of purpose-specific `uiStore` fields (one per level: `expandedTopLevelBranch`, `expandedProbeId`, `expandedCompanyId`, `expandedFleetParamsGroup`), not one generic node-id scheme — deliberately additive rather than a parallel selection-state representation of the tree.

**`useNavTree()`** (`src/components/panels/screen/nav/useNavTree.ts`) is the one place a node's generic string id (`<branch>[.<entityId>[.<section>]]`, e.g. `probes.r4.volume`, `companies.c2`, `fleetParams.eqFilters.eq`) is ever parsed — every other component (`NavTreeNode`, `ContentPane`'s content components) reads only its typed `isSelected`/`isExpanded`/`select`/`toggleExpand`, never the id itself. It also merges `navTreeConfig.ts`'s static schema with the two dynamic subtrees — one `probes.<robotId>` node per robot and one `companies.<companyId>` node per company in the active locale, both regenerated live (no remount) as the roster/company list changes.

**The 4 top-level branches and their real content**, per spec §2's Node → Content Mapping table:

| Branch | Bare category node | Leaf content |
|---|---|---|
| **Settings** | Landing doc (prose placeholder) | Volume (relocated `Header` slider) · Quality (`AudioLoadPanel`, relocated from Audio Rig) · Tempo (relocated BPM slider) · Sector Settings (`SectorSettingsDrawer`, unchanged) |
| **Fleet Params** | Landing doc; its 3 groups (EQ & Filters / Time & Space / Output) are category-only, no content of their own yet | Each of the 7 effects (EQ, HPF, LPF, Reverb, Delay, Compressor, Limiter) renders standalone via `AudioRigEffectPanel` — the group node itself and the bare branch both fall back to `AudioRigDrawer`, which by this point in the migration renders only the one control with no leaf of its own (Automatic Effects/Ping Variance Automation) |
| **Probes** | `RobotsTab`'s existing filterable card list (the browse view; company-filtering it now depends on visiting Companies first — see below) | **Probe *N*** (a specific robot): bare node shows `RobotDisplaySection` alone; Volume/Melody/Envelope/Source each show exactly one of `AudioSettingSection`/`PingControlsDrawer`/`PingContourDrawer`/`SignatureArrayDrawer`, scoped to that robot. **All Probes** (bulk edit — the one genuinely new piece of logic this rewrite added): bare node shows all 4 drawers bound to every robot in the locale; each leaf narrows to one. Reuses `CompanyOptionsSection`'s existing `allRobotsSelected`-driven "broadcast to every robot" mode rather than new wiring — a `uiStore.allProbesSelected` flag (distinct from `allRobotsSelected`, which is the Robots tab's own unrelated company-filter default) disambiguates this leaf from the bare browse list, since both otherwise read `selectedRobotId === null` |
| **Companies** | Create form (`CompanyCreateForm`, staged draft + submit) | **Company *X*** (a specific company): bare node shows `CompanyRenameDeleteForm` (Rename staged-draft form, Delete behind a Radix `AlertDialog` confirmation — the app's first confirmation dialog — plus a small read-only name/color/member-count summary); Volume/Melody/Envelope/Source each show `CompanyOptionsSection` narrowed to that one section, broadcast-bound to the company's members |

`RobotFilterPanel` and `CompanyManager`/`CompanyButtonRow` (the pre-rewrite company button row + CRUD sidebar that used to live inside the Robots tab) were deleted, not migrated — a deliberate scope decision, confirmed with Crawford: filtering the Robots list by company, and all Companies CRUD, now go exclusively through the Companies branch above. This is a real workflow change from the pre-rewrite app, not an oversight.

**`uiStore`'s nav-specific fields** (all plain JSON-serializable primitives, see the `uiStore` section below for the full list) exist because the tree deliberately has no single opaque "selected node id" — each level of "which thing is open/selected" gets its own small, typed field, added incrementally as each branch's real content was built out, rather than one generic scheme parsed everywhere.

**`AccordionContainer` retired** (`docs/specs/NAV_LAYOUT_REWRITE.md` Task 21) — every one of its former consumers (`AudioRigDrawer`, `PingControlsDrawer`, `PingContourDrawer`, `SignatureArrayDrawer`, `AudioSettingSection` — a 6th real consumer the original plan's own list of 5 missed) now renders its content as one tree leaf's content instead of a collapsible section; see [COMPONENT_LIBRARY.md](COMPONENT_LIBRARY.md) for its own historical record. The old per-drawer lazy-mount optimization (roadmap 17.2.2) became moot by construction, since `ContentPane` now mounts exactly one leaf's content at a time regardless.

**Robot Systems Engine (Phase 7) / Robot Selection (Phase 8) / Robot Options (Phase 9), unaffected by this rewrite:** the roster is fixed at exactly 12 robots created once per locale (no dynamic spawn/despawn — see [ROBOT_LIFECYCLE.md](ROBOT_LIFECYCLE.md)); `RobotsTab` renders one `RobotSelectionCard` per robot (avatar, job, battery, docking, an `AudioStatusBadge` colored dot); selecting one shows `RobotDisplaySection`/the 4 drawers as described in the Probes row above, all schema-driven from `src/data/robotOptionsConfig.ts` and live-wired to `AudioEngine`/`useLocaleStore`. See [COMPANIES.md](COMPANIES.md) for the Companies domain model (Phase 10) that the Companies branch above now edits through the tree instead of the old button-row UI.

## uiStore

UI-only, JSON-serializable state (`src/stores/uiStore.ts`): `activeView`, `theme`, `language`, `isPoweredOn`, `isFullscreen`, `activeLocaleLocalTime`, `activeLocaleTemperature` (`docs/specs/HEADER_HUB_CONSOLIDATION.md` — same shape/placement/no-persistence convention as `activeLocaleLocalTime`, purely decorative, read by nothing but `Header`), `selectedRobotId`, `selectedCompanyId` (Phase 10 — independent of `selectedRobotId`), `allRobotsSelected` (the Robots tab's own "All" company-filter default, mutually exclusive with `selectedCompanyId` — a different concern from `allProbesSelected` below despite the similar name), `activeHubTile`.

**Nav & Layout Rewrite additions** (`docs/specs/NAV_LAYOUT_REWRITE.md` §1.3, plus a few more added as real content gaps were found during implementation — see "Console Navigation" above): `selectedSection` (`RobotSection | null` — which of a robot/company/All-Probes' 4 leaves, Volume/Melody/Envelope/Source, is open), `isNavPanelOpen` (mobile only), `expandedProbeId`/`expandedCompanyId`/`expandedFleetParamsGroup`/`expandedTopLevelBranch` (one accordion-of-one field per tree level), `selectedSettingsLeaf` (Settings isn't an "entity" the way a robot/company is, so it needed its own field rather than reusing `selectedSection`), `selectedFleetParamsEffect` (reuses `AudioRigEffectKey` directly rather than a parallel string union), `allProbesSelected` (disambiguates the bare "Probes" browse node from the "All Probes" bulk-edit leaf — both otherwise read `selectedRobotId === null` with no other signal). `clearSelectedCompany` resets `selectedCompanyId` alone, without touching `allRobotsSelected` — used when navigating to the bare "Companies" node, a different concern than `selectAllRobots`. No Tone nodes, GSAP timelines, or DOM refs — the store's own comment says as much.

## Radix Primitives in Use

Installed and in use: `react-alert-dialog`, `react-dialog`, `react-dropdown-menu`, `react-popover`, `react-select`, `react-separator`, `react-slider`, `react-switch`, `react-tabs`, `react-toggle`, `react-toggle-group`, `react-toolbar`, `react-tooltip`, `react-visually-hidden`. Radix owns ARIA roles, focus trapping, and keyboard contracts; project design tokens own visual styling — don't install `@radix-ui/themes`.

## Forbidden Patterns

- Rendering any interactive control (buttons, inputs, nav) inside `SleeveContainer`.
- Storing GSAP timelines, DOM refs, or computed UI props in `uiStore` — only plain, serializable UI state.
