# UI Shell Guide

Rewritten from the shipped code for the layout rework ([Roadmap Phase 45](todo/roadmap.md), [spec](specs/LAYOUT_REWORK.md), [plan](tasks/LAYOUT_REWORK.md)). The nav tree and the stacked, scroll-synced accordion screens are gone; this guide describes what replaced them, not the history.

## Overview

Trace Atlas's UI is a "Sleeve & Glass" tablet shell. `Tablet.tsx` composes two decorative `SleeveContainer`s flanking a single `ScreenViewport`:

```typescript
<SleeveContainer hasPowerSwitch={true} />
<ScreenViewport isPoweredOn={isPoweredOn} />
<SleeveContainer />
```

- `SleeveContainer` (`src/components/panels/physical/`) is decorative housing: a logo mark and the `PowerRockerSwitch` when `hasPowerSwitch` is set. Nothing interactive lives there but the power switch.
- `ScreenViewport` (`src/components/panels/physical/`) is the interactive surface. `WorldView` is mounted in **both** power states: the world is built before power-on and is the off screen's backdrop (its systems start on the rocker, see [SESSION_STORAGE.md](SESSION_STORAGE.md)). Powered off it adds `OffScreen`; powered on it adds `Header`, `NavPanel`, `ContentPane`, `NavBreadcrumb` and `PhoneBar` (all under `src/components/panels/screen/`). It stamps `data-shell="desk" | "phone"` on its root, from `useShell()`, so a stylesheet reads the shell without a media query of its own.

**Guardrail** (see [CLAUDE.md](../CLAUDE.md)): all interactive UI — transport, navigation, controls — lives inside `ScreenViewport` only, never in `SleeveContainer`. Portalled UI (the help popover, the Move panel) portals into `ScreenViewport` itself, never `document.body`.

## Two shells, one switch

`useShell()` (`src/components/panels/screen/useShell.ts`) returns `'desk' | 'phone'` from one `matchMedia` query on `NAV_PANEL_DOCK_MIN_WIDTH` (768 px). Everything that differs by shell reads this hook and nothing else: the panel against the sheet, the header's contents, the lane titles, the `LfoLink` row, the meta box's lines. The 640–767 px band takes the phone shell with the larger cabinet tier. `useCabinetTier` (639 px) keeps sizing controls and is **not** a shell switch. `SHELL_MIN_WIDTH` (320 px) is the narrowest viewport the phone shell must hold; a CSS test walks every shell piece at that width.

| | Desk (768 px and up) | Phone (below 768 px) |
|---|---|---|
| Nav | `NavPanel`, a rail on the left edge | the same `NavPanel` in a modal sheet, opened from `PhoneBar`'s menu |
| Header | mute and the master volume slider, beside the power corner | mute and a ▾ box that opens the slider in a pop-out |
| Where am I | `NavBreadcrumb` along the bottom-left of the content surface | `NavBreadcrumb` in `PhoneBar`'s well |
| World line | `MetaBox`, top of the Deck | `PhoneBar`'s well, on the Deck |

## The nav panel

`NavPanel` (`nav/NavPanel.tsx`) is one panel of five parent boxes in the order Deck, Fleet Params, Probes, Companies, Settings, each in its branch's trait colour, in the panel's static popped cabinet facade; the open branch's box is popped out. A box is a `NavBox`. Probes and Companies **expand in place**: while `uiStore.expandedTopLevelBranch` is that branch, `NavEntityList` lists its entities under the box (All Probes, then the robots in their identity colours; or + New Company, then the companies) and the panel widens. The width is `--nav-panel-width` on `#screen-viewport`, derived in `NavPanel.css` from a rest and a wide size and an expand factor `--nav-panel-expand` that `NavPanel` tweens in a `timelineMap` timeline (`nav-panel-width`; the first value is set at once and so is every change under reduced motion). `ContentPane`'s left edge reads the same variable, so the panel and the content edge move together. Fleet Params and Settings are leaves: no list.

On the phone shell the same panel renders inside a modal Radix `Dialog` whose open flag is `isNavPanelOpen`, with a scrim, a focus trap and Escape. It is not in the DOM while shut, it has no `Dialog.Portal` (it renders inside `ScreenViewport`), and a pick closes it. `PhoneBar` owns the menu `Toggle` (☰ and ✕, the facade holding the larger glyph so the box never resizes) and a well beside it.

### `navActions.ts` — selection in one place

`nav/navActions.ts` is the one module that changes what is selected. The panel, its entity list, the breadcrumb, the roster board and the company screen all call it; no component derives a path itself.

- `selectBranch(branch)` opens a parent box's own page. Every action starts from a clean slate (no entity, no section on any branch, Fleet Params on its default tab, Settings on its first, the phone sheet shut) and then sets only what it opens.
- `selectEntity(entity)` opens a robot, a company or `'all'` (All Probes) with the list collapsed, so the entity's screen gets the panel's rest width.
- `pressBranchBox(branch)` is what a box press calls: on a branch's own page, Probes and Companies toggle their list in place; anywhere else it is `selectBranch`.
- `goHome()` is the Deck: no tile, nothing expanded, no entity.
- `breadcrumbTrail(state, roster)` returns the segments (each knows how to go back). `FLEET_PARAMS_SUBSECTIONS` and `SETTINGS_LEAVES` are the one table each of the Fleet Params sub-tabs and the Settings tabs, read by the screen and the breadcrumb alike, so they always name the same tab.

`NavBreadcrumb` is a passive "where am I" readout (a recessed well, `inBar` on the phone) built from `breadcrumbTrail`; reads `Root / branch / entity / section` (Root is left out on the phone), every ancestor a button that calls the matching navAction and the last segment plain text; it renders nothing on the Deck. `useEntityRoster` (`nav/useEntityRoster.ts`) is the narrow robots/companies subscription both the entity list and the breadcrumb share.

## The header

`Header` is one cabinet row beside the power corner, in the static popped facade: a Mute `Toggle` (🔇/🔊 swapped on `isMuted`) and the master volume `SliderLinear` bound to `audioStore.volume`. On the phone shell the slider sits behind a ▾ box in a Radix `Popover` pop-out (inside the header, not portalled). Volume lives here only (Settings has no copy of it), so it stays reachable beside mute and is never gated behind a nav selection. `Header` writes its measured height (`--header-height`) and the row's width (`--header-width`) to the document root, which the content surface and the meta box read.

## The content surface and the world

`ContentPane` (`console/ContentPane.tsx`) is the single area a selection opens into. At the Deck (`activeHubTile === null`) it renders only a small collapsible Welcome card (`.content-pane__home`, sized to its content, so `Robot.tsx`'s click-to-select reaches the world). Once a branch is open it renders `ConsolePanel` on an opaque plate, `--content-surface` (`src/index.css`): flat, no glass, right of the nav panel (`--nav-panel-width`) on the desk and edge to edge above `PhoneBar` on the phone. `WorldView` dims under it via a `data-dimmed` attribute on its root, set while a branch is open; panels inside keep the static popped `CabinetBox` facade in trait colour.

`ConsolePanel` routes by `activeHubTile` through a `Record<HubTile, …>` (a missing tile is a compile error): `robots` → `RobotScreen` when a robot is selected, `CompanyScreen` for All Probes, else `RosterBoard`; `companies` → `CompanyScreen` when a company is selected, else the same `RosterBoard`; `audioRig` → `FleetParamsScreen`; `settings` → `SettingsScreen`.

### The meta box

`MetaBox` (`worldView/MetaBox.tsx`) is the glow-glass well at the top of the Deck, desk shell only. It carries the `WorldLine` — clock and temperature, robots emitting against the Audio Load budget's cap, and the current Attenuation Style with its coordinates. On the phone, `PhoneBar` shows the same `WorldLine` in its well on the Deck. A selection reads as a halo, not as text: `Robot.tsx` sets `--halo` inline, the robot's own identity colour when selected, its company's when a member.

## The screens

Every screen below is a stateless view over the existing stores; the controls are the same schema-driven primitives ([COMPONENT_LIBRARY.md](COMPONENT_LIBRARY.md)). A screen's sections are `SectionTabs` — one section in the DOM at a time, no `forceMount` — so an inactive section's controls never exist (this carries roadmap 17.2.2's lazy mount forward).

| Screen | Content | Open tab |
|---|---|---|
| `FleetParamsScreen` | an intro, then five section tabs — Pacing, LFO Bank, EQ & Filters, Time & Space, Output — with a nested sub-tab row for the four lanes and the effect leaves | `fleetParamsSection` / `fleetParamsSubsection` |
| `SettingsScreen` | an intro, then three tabs — Audio Quality (`AudioLoadPanel`), Seeds (`SectorSettingsDrawer`), Save & Share (`SessionsPanel`, [SESSION_STORAGE.md](SESSION_STORAGE.md)) | `selectedSettingsLeaf`, resolved by `activeSettingsLeaf` |
| `RosterBoard` | the Probes and Companies pages: the head (All Probes, + New Company disclosing the staged `CompanyCreateForm`), then one row per group from `rosterRows()` — the companies, then Freelance — of `RosterTile`s with a Move chip ([COMPANIES.md](COMPANIES.md)) | — |
| `RobotScreen` | on the desk a fixed avatar column (the gem, the name, read-only meta, the battery and the company radio) beside `SectionTabs` over `ROBOT_SECTIONS_CONFIG`, Source with a sub-tab per oscillator; on the phone the column is a small sticky band | `selectedSection` / `selectedSubsection` |
| `CompanyScreen` | the robot screen with a company column (name, share and signal wells, member tiles, Rename / Delete) over the same four sections, edited through `useCompanyOptions`; the All form is the whole fleet | `selectedSection` / `selectedSubsection` |

Each section's panel opens with its group's intro as an expander that starts collapsed with its headline showing.

## The off screen

`OffScreen` (`screens/OffScreen.tsx`) is what shows while the power is off, over the still `WorldView` (roadmap 57; [spec](specs/OFF_SCREEN.md), [plan](tasks/OFF_SCREEN.md); the sketch `docs/sketches/off-screen.html` is the record of the look). Power is a **pause**, not a teardown: the rocker's off-click calls `powerController.pause()` after its 0.18 s hold, with no confirm dialog, and the world waits frozen behind the screen ([AUDIO_SYSTEM.md](AUDIO_SYSTEM.md#power-is-a-pause)). Only the aspect family rows come off the plate, popping on hover and select; everything else is flat: the Transmission row in `RadioButton`'s `list` appearance, the theme row, Scan and Keep `muted` ([COMPONENT_LIBRARY.md](COMPONENT_LIBRARY.md)). Revised 2026-10-31 after Crawford's listen ([plan](tasks/OFF_SCREEN_REVISIONS.md), his eight notes): the list, Roll in the Current row, three more aspect families, no "as theme", the popping rows, the veil held still and the scene wash. Revised again 2026-11-02, backlog 64 ([spec](specs/OFF_SCREEN_CURRENT_AND_NEW_TRANSMISSION.md), [plan](tasks/OFF_SCREEN_CURRENT_AND_NEW_TRANSMISSION.md)): Current stays the world you powered off on, a New Transmission row with Scan in it replaces Roll, a theme or aspect click keeps the selected row, and Keep saves Current.

- **The veil and the theatre.** The screen's own backdrop, `off-screen__veil` (`backdrop-filter: blur(3px)` over a dark tint), blurs and dims the world under everything else; a lore footer (`home.off.footer`) is the last thing in the column in both gate states, its text at 0.55 alpha so it reads at about 4.5:1 over the world (`docs/tasks/OFF_SCREEN_FINAL_FIXES.md` F4, the measurement recorded there). On a fresh page the dark layer `off-screen__dark` holds for 0.5 s and flickers off over 1 s (`animation/offScreenTheatre.ts`, a `'ui'` timeline in `timelineMap`, so it plays over the paused world); a tap anywhere skips it (the dark layer takes the tap, so it selects nothing it hides), `prefers-reduced-motion` skips it outright, and the rocker works throughout. After a power-off (the world `'paused'`) there is no flicker: the screen fades in over the world just frozen, the reverse of the power-on fade (`fadeInOffScreen`: the dark layer hidden at once, the veil and the column from transparent over 0.4 s, the `'ui'` timeline `off-screen-fade-in`; F6). On the flip the screen and its veil fade over 0.4 s (`fadeOffScreen`), which `powerController.powerOnSequence()` awaits before anything wakes, so nothing shows unveiled under the chrome; the screen is `inert` from the fade's start, and a start that fails gives it back (`restoreOffScreen`; `docs/tasks/OFF_SCREEN_REVIEW_FOLLOWUPS.md` R19). One fade at a time: a second press during the fade joins it (one promise, resolving `'done'`, or `'cancelled'` when `restoreOffScreen` kills it), a press whose fade ends during another's cold start joins that start, and a press whose fade a failed start cancels starts nothing (`docs/tasks/OFF_SCREEN_FINAL_FIXES.md` F1, F13). The screen's root never scrolls: it holds the veil, the dark layer and the column `off-screen__scroll`, in that order, and the column scrolls inside it, so the veil and the dark layer stay put over a moving column. On the phone the column starts at the top, its top padding clearing the power corner (`calc(var(--power-corner-height) + 12px)`); on the desk it is centred while it fits (`justify-content: safe center`). Either scrolls once it outgrows the screen.
- **The gate.** A device that has never heard a world (`hasHeardWorld()`, `src/utils/deviceFlags.ts`: `localStorage['trace-atlas.device.v1']`, written by the first cold start, cleared by Factory Reset) sees the etched label, the power hint and the footer only. From the first power-off on, the chooser.
- **Two axes.** Desktop shows them side by side (`.off-screen__axes`), the phone stacks them; a `role="status"` readout spanning both names the pick through `describeWorld` (`src/utils/describeWorld.ts`: `AS · (x, y)`, a save's or preset's name in front, then ` · <Theme>` and one ` · A + B` per family with picks, in family order). **Transmission — which world:** a `RadioButton` in the `list` appearance, one full-width row per option, every row naming its world through `describeWorld`:
  - **New Transmission**, first and unselected on open, holds a world drawn on mount (`generateRandomAttenuationStyleName()` at `randomCoordinate()`s), named by its eyebrow over that world ("New Transmission, …"; `home.off.newTransmission`). Picking it lands the drawn world under Classic with no aspects (`retransmitWorld({ attenuationStyleName, coordinates, theme: 'classic', aspects: {} })`) and detaches the loaded save. **Scan** (`home.off.scan`), a muted `Button` in the row's end (the list's `trailing` slot, beside the radio and never inside it), draws another world into the row and picks it, from any selected row, New Transmission included. The draw is runtime only and the next off screen draws afresh.
  - **Current**, named with its eyebrow ("Current, …"), is the world you powered off on. With nothing left yet it is the live world, named from the stores (or the loaded save's name in front). The first pick of another row takes a **snapshot** of it (`buildSessionPayload()` and the loaded save's name, component state, never a store, a save or the link), and from then on Current is named from the snapshot, so no pick renames it. Picking Current while the other row's change still waits under the wash cancels that change (`cancelWorldChange`) and drops the snapshot, so the paused world stands. Picking it after another world has landed restores the snapshot, a world change under the wash: `applySessionPayload(snapshot.payload)`, then the snapshot's save re-attached (or the save detached if it had none), and the snapshot dropped, so Current is live again. A restore after a landed change rebuilds cold, so the next flip starts the world rather than resuming it.
  - **Saved Transmissions**, the saves newest first, under that title while there are any, each named `<name> · <world>` and saying when it was saved ("saved …", `home.off.savedAt` over `formatSessionTimestamp`); a divider (only when there are saves); then **Preset Transmissions**, the three presets, named the same way. The titles are `RadioButton`'s `headingBefore` ([COMPONENT_LIBRARY.md](COMPONENT_LIBRARY.md)). A preset is a world link (`TransmissionPreset = { id, nameKey, link }`, `src/data/transmissionPresets.ts`; `presetPayload` decodes it through `decodeWorldLink`).

  After a power-off the chooser takes the focus on its selected row; a fresh page leaves the focus alone (`docs/tasks/OFF_SCREEN_REVIEW_FOLLOWUPS.md` R25). Picking a save or preset retransmits the faint world through `applySessionPayload` and never starts audio; only the rocker does. Power-on plays whichever world is live, and at the next power-off it is Current. The selected row other than Current, once its live loading differs from its own (after a theme or aspect click), names the live loading in place of its own, the theme named whenever it differs from the row's, Classic included ("Harbour Song · tr3nch-2 (-30, -30) · Classic"; `describeLoading` and `withTail` in `describeWorld.ts`). It reads as stored again once left, and a save or preset picked again reloads as stored. Nothing of the edit is written to storage. **Keep**, a muted `Button` alone under the list and labelled "Save Last World", saves Current, no name field. With no snapshot it is `sessionStore.keepCurrentWorld()`: the live world under the loaded save's name or, with nothing loaded, the suggested name unless a save already has it, in which case a name no save has (`docs/tasks/OFF_SCREEN_REVIEW_FOLLOWUPS.md` R6). With a snapshot it is `sessionStore.keepWorld(snapshot.payload, snapshot.loadedName)`: the snapshot under its save's name or a fresh unused one, which the snapshot then carries, so Current is named after it and a restore attaches it; no session field moves, since those describe the live world. Either way the saves are read again, so the new row appears. Keep dims whenever Current equals its save (`isWorldDirty()` with no snapshot, `isPayloadDirty(snapshot.payload, snapshot.loadedName)` with one), and while a world change waits under the wash; a muted warning line sits under the chooser while Current is unsaved, or the failure line in its place after a Keep the storage refused (R20). **Loading — how it loads:** the theme row (the fourteen `THEME_IDS`, labelled `home.off.loading`, shown as "Trace Type" with the hint "select one") with the shown theme's one-line description under it, then a "Trace Aspects" title with the hint "select many" (a standalone `DualLabel`), then one `multiple` `RadioButton` per aspect family in the cabinet appearance, rendered from `ASPECT_FAMILY_IDS`: Melody (Hypnotic, Mechanical, Wandering, Chanting, Tumbling, Telegraph), Envelope (Plucked, Swelling, Held, Bowed, Hammered, Breathing), Distance (Near, Echoing, Half-heard), Voice (Glassy, Woody, Hollow, Brassy, Muted, Chiming), Motion (Gliding, Trembling, Sweeping) and Performance (Steady, Dramatic, Halting), each in canonical order (the set as of roadmap 58, `docs/specs/THEME_AND_ASPECTS_REFINEMENT.md`), each with its own line naming the aspect toggled on last, else the last of its set, else the family's `none` sentence. There is no As theme option: a cleared row is every robot as theme in that family. A theme change is `retransmitWorld({ theme })`: the same seed, plot and live world, and only the attributes the theme moves written in place, global and robot alike (the tempo, the Low-Pass cutoff, the Sync picks the tempo moves, the robot fields its bands move), at the click, with no rebuild and no wash (`loadingOnly`; `docs/tasks/OFF_SCREEN_FINAL_FIXES.md` F7–F8, F17). A family change sends the whole loading with that family's set replaced, `retransmitWorld({ aspects })`: the live roster is re-derived in place at the click, only the fields the new picks move, with no rebuild and no wash (`aspectsOnly`, R33; field by field since F16). Either way a tweak on any other attribute stands. Either keeps the selected row: on Current it changes Current itself (the live world, or a waiting restore's), and on any other row it edits that row's world in place, its label showing the live loading as above. The Loading rows show the waiting change's loading while one waits, else the live loading store's, whichever row is selected.
- **Pick rules.** A save pick names the session after the save, so a later Save overwrites it; a preset pick, a New Transmission pick or a Scan detaches the loaded save (`detachLoadedSession`); a theme or family pick keeps the save attached (the seed is still the save's); a Current restore re-attaches the snapshot's save, or detaches if it had none. Re-clicking the selected row does nothing. While a world change waits under the wash, every click joins it (R3): the rows show the click at once, the one change realises all of them when the cover lands, and the last world click wins, a Current restore included (a pick made while a restore waits replaces it, and the snapshot stays). A theme or family click made then joins the waiting change's loading, laid over its world at the cover, and the row stays the intended pick, always. The one exception is Current picked before the change it would leave has landed: that cancels the change rather than joining it. The readout names the selected row's world: the intent's while a change waits, else the live world under the row's name (Current's is the snapshot's or the live loaded save's, a save's or preset's its own, New Transmission's none). The saves are read on mount and again after a Keep; a save that has vanished from storage applies nothing.
- **The address bar follows the loaded world.** Every pick, Scan, Current restore, theme or family change and Retransmit ends in `mirrorWorldToUrl` (`seed`, `x`, `y`, `theme` when not Classic, one param per family with picks, `melody=`, `envelope=`, `distance=`, `voice=`, `motion=` or `performance=`, and no `s`); a link arrival's URL stands until the world changes. A world changed while the tablet is off is rebuilt cold, so the next flip starts it rather than resuming; a theme or family change rebuilds nothing, so the world stays paused and the flip resumes it.
- **The scene wash.** A user-gesture world change fades the old world out and the new one in: the off screen's save, preset and New Transmission picks, Scan and a Current restore, Foundry's Retransmit and a session Load each wrap their change in `requestWorldChange` (`src/systems/worldChange.ts`). The wash, `div.world-view__wash` in `WorldView` (over the scene, under `MetaBox`, `pointer-events: none`), fades to the water column's own colours at the hour over 0.5 s; the change runs under it, and it fades out over 0.5 s. While the tablet is off it reads as a tint through the veil's blur. The caller's own follow-ups (the pick, the session names, Keep's dirty read) run inside the request, after the change. Picking Current with nothing landed (it cancels a waiting change, or applies nothing), the theme row (re-derived in place, F7–F8), a family row (re-dealt in place, R33), Keep and an unedited Retransmit are not world changes and never wait (a theme or family click made while a change waits joins it); the boot and a link arrival never wash; reduced motion cuts straight to the new world. The timeline and the four states are in [ANIMATION_SYSTEM.md](ANIMATION_SYSTEM.md#the-scene-wash).

Foundry (Settings → Seeds, `SectorSettingsDrawer`) lost its Attenuation Style and coordinate shortcut buttons to the presets; its status line is `describeWorld` of the loaded identity, so it, the Current row and the readout agree byte for byte. See [SESSION_STORAGE.md](SESSION_STORAGE.md) for the payload, the link params and the presets.

## uiStore

UI-only, JSON-serializable state (`src/stores/uiStore.ts`): `isPoweredOn`, `activeLocaleLocalTime` (the wall-clock hour, 0–24), `activeLocaleTemperature` (decorative, read by the world line and the header), and the selection fields below. No Tone nodes, GSAP timelines or DOM refs.

| Field | Meaning |
|---|---|
| `activeHubTile` | which branch is open (`null` = the Deck); the branch's box in the nav panel is `branchOfTile(activeHubTile)` |
| `selectedRobotId`, `selectedCompanyId` | the open robot or company; independent of each other |
| `allRobotsSelected` | the "no company" state (the default); mutually exclusive with `selectedCompanyId` |
| `allProbesSelected` | the All Probes form (a bulk edit over the whole fleet); distinguishes it from the Probes roster, both of which read `selectedRobotId === null` |
| `selectedSection`, `selectedSubsection` | the open robot/company tab and sub-tab, resolved by `robotSubsectionConfig`'s helpers |
| `fleetParamsSection`, `fleetParamsSubsection` | the open Fleet Params tab and sub-tab; setting the section clears the sub-tab |
| `selectedSettingsLeaf` | the open Settings tab (`null` = Audio Quality) |
| `expandedTopLevelBranch` | which of Probes/Companies lists its entities in the panel |
| `isNavPanelOpen` | the phone sheet's open flag; the desk panel ignores it |
| `movePanelRobotId` | the robot whose Move panel is open on the roster board (at most one) |
| `sceneWash` | the scene wash's state, `'clear'`, `'covering'`, `'covered'` or `'uncovering'`: `requestWorldChange` sets `'covering'`, the wash's timelines set `'covered'` and `'clear'`, and the request module sets `'uncovering'` once the change has run |

## Radix Primitives in Use

Installed and in use: `react-alert-dialog`, `react-dialog`, `react-popover`, `react-slider`, `react-switch`, `react-tabs`, `react-toggle`, `react-toggle-group`, `react-visually-hidden`. Radix owns ARIA roles, focus trapping and keyboard contracts; project design tokens own visual styling — don't install `@radix-ui/themes`. The two sheets on the phone (nav and Move) are `Dialog`s; the help "?" and the desk Move panel are `Popover`s; `SectionTabs` is `Tabs`.

## Forbidden Patterns

- Rendering any interactive control (buttons, inputs, nav) inside `SleeveContainer`.
- Portalling UI out to `document.body`; portal into `ScreenViewport`.
- Branching on the viewport anywhere but `useShell()` (or `useCabinetTier()` for control sizing).
- Deriving a breadcrumb or a selection in a component; go through `navActions.ts`.
- Storing GSAP timelines, DOM refs or computed UI props in `uiStore` — only plain, serializable UI state.
