# Procedural Generation & Seeded Determinism

Source of truth: [`src/utils/seedUtils.ts`](../src/utils/seedUtils.ts) · [`src/utils/noiseMaps.ts`](../src/utils/noiseMaps.ts) · [`src/utils/getSeededVal.ts`](../src/utils/getSeededVal.ts)

**Related docs:** [MELODY_SYSTEM.md](MELODY_SYSTEM.md) · [ROBOT_DESIGN.md](ROBOT_DESIGN.md) · [AUDIO_SYSTEM.md](AUDIO_SYSTEM.md)

## What It Is

Trace Atlas replaces `Math.random()` with a deterministic noise-based sampler almost everywhere game logic needs randomness. The guarantee: **the same Attenuation Style name + the same locale coordinates always produce the same world** — same robot names, audio attributes, melodies, work sites and charging stations. Nothing about the generated world is persisted beyond the seed inputs themselves.

An **Attenuation Style noise map** is seeded from the Attenuation Style's own name and used for genuinely Attenuation-Style-level generation — the global Audio Rig chain, global LFOs (see [AUDIO_SYSTEM.md](AUDIO_SYSTEM.md)), the transport tempo (`generateAttenuationStyleBpm`, `src/utils/bpmSeed.ts` — seeded per Attenuation Style, no longer per locale), the Free-vs-Sync roll on each LFO lane and on the Delay (`globalAudioSeed.ts`), and the additive AS-seeded factory color shift (`deriveAsColorShift()` — see [BUILDING_DESIGN.md](BUILDING_DESIGN.md)). A **locale noise map** per locale is seeded independently, derived directly from that locale's own `(x, y)` coordinates — **not** from the Attenuation Style at all. Individual values (a robot's attack time, a spawn X position, an idle target) are then sampled from the relevant locale's noise map via a stable string key. World time (`dayStartTimestamp`) lives on `Locale` too, computed directly from a locale's own `x` coordinate — not seed-derived, and not an Attenuation-Style-level value at all (see [docs/specs/ATTENUATION_STYLE.md](specs/ATTENUATION_STYLE.md)).

**Not covered here:** factory/building variant selection (`selectVariantFromSeed` in `src/components/actors/factoryVariants.ts`) is a separate, self-contained deterministic mechanism — it seeds its own `Alea(actorId)` PRNG per call and never touches the noise-map registry described below. See [BUILDING_DESIGN.md](BUILDING_DESIGN.md) for that system.

## Seed Derivation (`seedUtils.ts`)

```typescript
deriveAttenuationStyleSeed(name: string): string   // lowercase, strip non a-z0-9 — "Pelagos 7!" → "pelagos7"
```

`deriveAttenuationStyleSeed` is pure: the seed is the name alone, and nothing overrides it. (A module-level seed and coordinate override, with its `?seed=` / `?x=` / `?y=` entry points and a `window.__GLOBAL_ATTENUATION_STYLE_SEED__` hook, existed until roadmap 56 deleted it; see [specs/SHORT_WORLD_LINK.md](specs/SHORT_WORLD_LINK.md) assumption 10.)

```typescript
generateRandomAttenuationStyleName(): string   // 8 chars of a-z0-9: a fresh world's name
randomCoordinate(): number                     // one integer axis: a fresh world's x or y, and the "Random" button's
```

### Reproducing a world: share its link

**To reproduce a world, share its world link** (Settings → Seeds → Copy link; [SESSION_STORAGE.md](SESSION_STORAGE.md#shareable-links-phase-21-the-world-link-since-roadmap-56)): `?seed=<name>&x=<int>&y=<int>`, the exact Attenuation Style name and the locale coordinates, plus an `s=1.<blob>` param carrying whatever was edited away from the seed. The triple alone pins the whole generated world:

- **The name** seeds the *Attenuation Style* noise map (global Audio Rig, global LFOs, the tempo and the Free | Sync rolls, audio swells, AS-level factory placement). It is used exactly as given; only the derived seed is lowercased and stripped, so `Pelagos 7!` and `pelagos7` make the same world under two names.
- **The coordinates** seed the locale noise map (robots, temperature, work sites) and the time-of-day phase (`dayStartTimestamp`, derived from `x`).
- **Each part falls back on its own.** A missing or malformed part takes what a fresh world would get for that part alone (`generateRandomAttenuationStyleName()` / `randomCoordinate()`): `?x=5` pins `x` and leaves the name and `y` random, and a non-integer coordinate is random, as is one past the safe integers (`Number.isSafeInteger`: a 400-digit `x` once read as Infinity and made a NaN day; `docs/tasks/OFF_SCREEN_REVIEW_FOLLOWUPS.md` R23). `decodeWorldLink` (`src/utils/worldLink.ts`) reads the link once, at module load, and the two stores build the default world from it before first render.
- **Boot-time only.** Sector Settings' "Random" coordinate button calls `randomCoordinate()` as before, and any locale added later takes its coordinates from the user, not from the link.
- **What pinning both still doesn't guarantee:** `Math.random()` remains only in `factoryPlacementSystem.ts`'s default `scale` parameter (overridden by the seeded value on the normal path), and in UI-only rolls (`CompanyCrudControls.tsx`, `realWorldGradient.ts`). Simplex-seeded values are fully reproducible; live behaviour that depends on wall-clock time (`dayStartTimestamp` is `Date.now()`-relative, so the *hour* is reproducible but the timestamp is not) and on user/scheduler timing is not. Treat a pinned world as "same generated content", not "same audio sample-for-sample".

## Noise Map Registry (`noiseMaps.ts`)

Two module-scoped `Map`s — **non-serializable, never put these or their contents in Zustand**:

```typescript
getAttenuationStyleNoiseMap(attenuationStyleId: string, attenuationStyleName: string): NoiseFunction2D
getLocaleNoiseMap(localeId: string, x: number, y: number): NoiseFunction2D
tryGetLocaleNoiseMap(localeId: string): NoiseFunction2D | null   // non-throwing; null if not yet registered
evictAttenuationStyleNoiseMap(attenuationStyleId: string): void
evictLocaleNoiseMap(localeId: string): void
```

- **Attenuation Style map:** `createNoise2D(alea(deriveAttenuationStyleSeed(attenuationStyleName)))`, cached by `attenuationStyleId`.
- **Locale map:** `(x, y)` are concatenated into a single string key (`` `${x}:${y}` ``) and that string seeds `createNoise2D(alea(...))` directly, cached by `localeId`. **Two locales with identical `(x, y)` — regardless of which Attenuation Style either one is on — get identical noise maps.** This is a deliberate design guarantee, not an accident: `x` and `y` are two independent inputs at the UI layer (Sector Settings' coordinate entry), but they collapse into exactly one seed value here, never two separate dimensions sampled through a noise function. This also structurally eliminates the coordinate "dead zone" bug the old Attenuation-Style-sampled derivation had (simplex noise degenerating toward zero at lattice-aligned points like `(0,0)`) — there's no simplex sampling left in the derivation step to collapse. See [docs/specs/LOCALE_SEED_DECOUPLING.md](specs/LOCALE_SEED_DECOUPLING.md) for the full rationale.
- **Lifecycle:** `attenuationStyleStore.ts` and `localeStore.ts` prime the default Attenuation Style/locale's maps eagerly at module scope (so they exist before first render) and again inside `addAttenuationStyle`/`addLocale`. `removeAttenuationStyle`/`removeLocale` call the matching `evict*` function; `removeAttenuationStyle` also evicts every locale map belonging to that Attenuation Style.
- `tryGetLocaleNoiseMap` exists specifically for hot-path callers (`AudioEngine`) that must not throw or block if a locale hasn't been registered yet.

## Sampling Values (`getSeededVal.ts`)

```typescript
precomputeDataX(dataId: string): number
getSeededVal(noiseMap: NoiseFunction2D, dataId: string, offset?: number, min?: number, max?: number): number
getUniformSeededVal(noiseMap: NoiseFunction2D, dataId: string, offset?: number, min?: number, max?: number): number
getCentredSeededVal(noiseMap: NoiseFunction2D, dataId: string, offset?: number, min?: number, max?: number): number
```

Three draws share one signature, so a call site moves between them by its function name alone (Even Seeded Draws, 2026-11-02, [docs/specs/EVEN_SEEDED_DRAWS.md](specs/EVEN_SEEDED_DRAWS.md)):

- `precomputeDataX(dataId)` turns a stable string key into a deterministic float via `alea(dataId)()`. **Hot-path callers must call this once at module scope and cache the result** — repeated calls do string hashing and are measurably slower than `Math.random()`, which matters on the audio scheduling path. `AudioEngine.ts`'s `VELOCITY_ROLL_X`/`VELOCITY_VARIANCE_X` (computed once at import) are the canonical example.
- `getSeededVal(noiseMap, dataId, offset, min, max)` is the **plain draw**: it calls `precomputeDataX` internally, samples `noiseMap(x, offset)` (simplex noise, `[-1, 1]`), and rescales to `[min, max]` (defaults `0..1`). One sample of a smooth field: neighbouring offsets read nearby values, which is what a smooth walk wants (the terrain profile, the temperature steps, the light shafts) and what a pick does not. Across worlds it is bell-curved (the outer tenth at each end of a band gets 0–8 % of draws instead of 20 %), welded (keys whose hashed x land close together read nearly the same value: 217 of 1,128 robot key pairs correlated above 0.9) and coarse at offset 0 (some global keys took 3 values in 3,000 worlds). Spec §1.1 has the measurements. **No audio value draws it any more**; the world and visual draws still on it are backlog [46](todo/backlog.md#46-world-seeded-draws-are-welded-and-centre-heavy-names-colours-gems-companies-placement)'s to sort into picks and walks.
- `getUniformSeededVal(noiseMap, dataId, offset, min, max)` is the **even draw**: three plain samples at `offset + [0, 137.42, 911.77]`, joined and hashed through `alea()` for one uniform value in `[min, max)`. Thousands of distinct values at every offset, every tenth of a band at about 10 %, no two keys correlated (none above 0.1 in 2,065 robot pairs or 6,670 global pairs after the switch). Every audio draw uses it: the robot bands (`robotFieldDerivation.ts`, `spawnSystem.ts`), the Audio Rig, LFO Bank, global links, pacing and colour draws (`globalAudioSeed.ts`), the tempo (`bpmSeed.ts`), every swell roll (`audioSwells.ts`) and the docked pitch drift (`robotSystems.ts`), each at the dataId and offset it always had. **An edge is the share it says**: a `lit` of 0.25 lights a quarter of robots, a trigger edge of 0.125 fires an eighth of ticks. The fitted thresholds of the plain-draw days were reset to their targets at the switch (spec §1.4).
- `getCentredSeededVal(noiseMap, dataId, offset, min, max)` is the **centred draw**: the mean of two even draws (`dataId` and `${dataId}.centre`, same offset), a triangle peaking at the band's middle, each outer tenth about 2 %. For the values whose middle is neutral: the three EQ bands (`globalAudioSeed.ts`), the robot detune and each layer's detune (`spawnSystem.ts`, `robotFieldDerivation.ts`), and a lit detune LFO link's depth, whose neutral is the window's 1 % floor, so `detuneLinkDepth` (`spawnSystem.ts`) draws it centred over −1..1, folds it and floors it onto the whole-percent grid (1 % the commonest depth, 10 % the rarest; spec §1.2).

**Tests steer a draw through `src/testUtils/seededDraws.ts`**, never a constant stub: a constant noise map lands every plain draw at one value but the even and centred draws hash their samples, so the helper's maps carry a tag naming their raw values and `steerSeededDraws(actual)` (the `vi.mock` factory, imported inside the factory because `vi.mock` is hoisted) makes all three draws read the tag. `constantNoiseMap(raw)` steers every key alike; `noiseMapForDataIds({ dataId: raw }, fallback)` steers named keys. `spawnSystem.test.ts`'s `forceSeededDraws` forces one dataId whichever draw makes it, so a test survives a call site moving between the three.
- `dataId` is a stable, human-readable, dot-namespaced key — conventionally the state path it fills (e.g. `'robot.audio.attack'`, `'spawn.pos.x'`). Renaming a `dataId` string changes the seed for every world that used it — treat renames as breaking changes to world generation.
- `offset` is what makes repeated calls with the same `dataId` diverge — typically a spawn count or robot index (e.g. `'robot.compositionSeed'` uses the robot's own `spawnCount`).

The rhythm and the stamps are no noise-map draws either: they are `alea` streams on the world's coordinates and the
rhythm shape (Melody's call-site row above), and a member's rhythm is its founder's because its settings are.

**Not noise-map draws any more:** the per-note rolls the playback loop makes — the velocity roll and its variance, and the Humanize
offset — are `performanceRoll(compositionSeed, purpose, position)` in `AudioEngine.ts`, an `alea` hash of the robot's seed, the
purpose and the tick (Robot Performance T20). They used to sample the noise map at `compositionSeed + position`, but
`robot.compositionSeed` is a 0–1 fraction, so every robot sat within one unit of the others on a smooth field and the whole roster
rolled together. `audio.velocityRoll` / `audio.velocityVariance` remain only for the legacy no-position path. The lesson generalises:
`compositionSeed` is a fraction, so anything "per robot" must hash it, never add it to an offset.

Until Even Seeded Draws (2026-11-02) every threshold was fitted to the measured plain draw rather than set to its nominal fraction: those draws bunched around 0.5, so a nominal 12 % threshold of 0.12 landed near the 3rd percentile. Every audio draw is even now and every edge is its share; the before-and-after table is spec §1.4, and `robotFieldDerivation.test.ts` and the `spawnSystem.even*.test.ts` files pin the shares over thousands of seeded robots. Adding these, and the switch to even draws after them, changed what every world sounds like, which pre-v1 is by design.

## Gotchas

- **Retiring `FACTORY_ROWS` (roadmap Phase 42) is an accepted breaking change to world generation.**
  Every locale now draws a district (`'locale.district'`) and places that district's recipe instead
  of the old single fixed row table — existing coordinates and shared links (then `?session=` links) regenerate a
  different-looking locale, by design (see docs/specs/WORLD_VIEW_DISTRICTS.md §6, intent "Out of
  scope"). No `dataId` was renamed; only the row table and its reader changed.
- Don't call `getSeededVal`/`precomputeDataX` inside a per-note audio callback without precomputing the `dataId` → x-value first (see `precomputeDataX`'s hot-path warning above).
- Don't rename a `dataId` string casually — it's a de facto seed key, not just a debug label.
- Don't store a `NoiseFunction2D` (or anything derived from the registry) in Zustand — it's a closure, not serializable.
- `getLocaleNoiseMap` silently creates-and-caches on first call; there's no way to "re-seed" an existing locale without evicting it first.
- **`offset=0` (the default) can silently collapse a single-value field's variety if its `dataId` happens to hash near a simplex lattice vertex.** `simplex-noise`'s `createNoise2D` evaluates to exactly `0` at `(0, 0)` for every possible seed, and stays degenerate near it — the same failure mode already called out above for the old Attenuation-Style-sampled locale derivation, but it can recur for *any* `dataId` string whose `precomputeDataX()` hash lands close to an integer coordinate, not just locale coordinates. Concretely hit this while building (and later cutting — see [CONSOLE_THEMING.md](CONSOLE_THEMING.md)) the Console Theming phase's now-removed `consoleTheme.ts`: `'ui.theme.background.hue'` hashed to `x≈0.0083`, and sampled at the usual `offset=0`, 50 random Attenuation Styles collapsed to only 3–4 distinct hues instead of a full spread. Fixed there (while the module still existed) with a fixed non-zero, non-integer offset rather than changing this function's own default. If a new single-value `dataId` ever shows suspiciously low variety across many seeds, check `precomputeDataX(dataId)` for a near-zero (or otherwise near-integer) result before assuming the noise itself is at fault. The one live single-value draw that follows this rule today is `'factory.as.accentPrimary'` (`ACCENT_PAIR_OFFSET = 0.37`, `factoryPlacementSystem.ts`); its test file carries both an offset spy and a measured spread guard over 50 real seeds, so a regression here fails loudly.
- **The other fix: hash several samples — the even draw.** `getUniformSeededVal(noiseMap, dataId, offset, min, max)` (`src/utils/getSeededVal.ts`) takes three samples at `offset + [0, 137.42, 911.77]`, joins them, and hashes the string through `alea()` for one uniform value. `pickDistrict` (`'locale.district'`) and `stations.ts` (`'station.*'`) were its first users; since Even Seeded Draws (2026-11-02) every audio draw makes it, or the centred draw built on it (see Sampling Values), and the plain draw is kept for the smooth walks and for the world keys backlog 46 still has on it. A plain draw is also welded: keys whose hashed x land near each other read nearly the same value, so on the plain draw a glider was almost always a sparse robot (r 0.999), and the three EQ bands moved as one. This fixes all three problems at once: the collapse near the lattice, the welding, and simplex output's bell curve (raw values bunch near the middle of the range). Measured on the stations (roadmap Phase 43 Task 13): with one `'station.count'` sample at offset 0, the draw took about 3 values across all 121 grid worlds, and no world ever rolled 3 stations. First stations clumped too, with 86 distinct centres over 121 worlds. With three samples hashed, there are 121 distinct first centres and 50 of 121 worlds roll 3. Re-hashing *one* sample through `alea()` flattens the bell curve but does not fix the collapse: `'locale.coverage.x'` did that until the Phase 43 review, and at offset 0 it put every world's first coverage top-up at one of 3 x positions across the 121-world grid. It now uses `getUniformSeededVal`. `rollDerelict` (`'actor.derelict'`) still re-hashes one sample per actor.
