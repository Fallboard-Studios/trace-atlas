## What it does

The **Save & Share** tab — third and last of Settings' three tabs, after Audio Quality and Seeds (`SETTINGS_LEAVES`, `src/components/panels/screen/nav/navActions.ts`; `SettingsScreen` is the tab row, [UI_SHELL.md](UI_SHELL.md)) — renders `SessionsPanel.tsx`. An operator types a name (or accepts the generated suggestion) and clicks "Save Session" to write the current audio-relevant tuning to `localStorage` under that name; a successful save shows a "Saved `${name}` at `${date + time}`" confirmation banner. Clicking a saved entry's "Load" button applies it immediately, no confirmation; clicking its "Delete" button removes it, behind an `AlertDialog` confirm. **There is no automatic/background saving of any kind** — the only way a session is written to storage is an explicit "Save Session" click. This is local, manual persistence — no automatic sharing, no compression — plus an explicit "Share Session" action (Phase 21, see below) that turns a payload into a URL on demand.

## What Gets Persisted

Robot attributes are already fully derived from the active Attenuation Style and locale coordinates — [PROCEDURAL_GENERATION.md](PROCEDURAL_GENERATION.md) guarantees the same seed always regenerates the same world. So a `SessionPayload` (`src/types/session.ts`) does **not** store full robot/company state. It's a diff reapplied on top of a freshly regenerated roster:

1. `attenuationStyleName` and `coordinates: { x, y }` — the active Attenuation Style and locale
2. `globalAudio: GlobalAudioSettings` — Audio Rig FX (Compressor, EQ3, LPF, HPF, the three Colour effects Distortion, Chebyshev and BitCrusher, the six Modulation pedals AutoWah, Phaser, Chorus, Tremolo, Vibrato and Frequency Shifter, Delay, Reverb, the Stereo Widener (Width), Limiter)
3. `robotOverrides: Record<robotId, RobotAudioOverrideDiff>` — only robots whose live values differ from what the seed alone would produce, and only the fields that differ: `adsr` (the whole envelope, so its optional `attackCurve` / `releaseCurve` ride along), `layers`, `filterFreq` (`AudioAttributes.filterFreq` — the bus filter cutoff, now editable in Source → Filter), `filterQ` and `filterType` (the bus filter's resonance and type), `portamento` (glide seconds), `rhythmicDensity`, `rhythmicMotifLength`, `noteVariance`, `pitchRepeat`, `octaveRange`, `lfoSettings`, `name`, `pan` (only for a robot whose Auto is off — see "Robot Pan across a save and a share link" below), and `reverbSend` / `delaySend` (only when a send differs from its seeded value — see "Robot Sends across a save and a share link" below). An untouched robot has **no key** in this map, not a key mapping to `{}`.
4. `companyDiffs: Record<companyId, CompanyDiff>` — spawn-generated companies only, same "no key if untouched" rule, covering just `name`/`robotIds` (membership)
5. `userCreatedCompanies: Company[]` — companies made via `CompanyCrudControls` (`crypto.randomUUID()` ids) have no seed to regenerate from, so they persist as **complete objects**, never diffed
6. `version: 1` — a schema-version field on the payload itself. Still unused by any code as of Phase 21 shipping — `decodeSessionPayload` (`sessionShareUtils.ts`) validates `attenuationStyleName`/`coordinates` presence, not `version`'s value — but the field travels through the share-link encoding unchanged, ready for a future payload-shape migration to branch on without a retrofit

**Explicitly never persisted:** `docking` and `batteryLevel` (they change every measure; a restored world respawns its roster from the seed, and the World Clock replay that could recompute them has no consumer yet — see [ROBOT_LIFECYCLE.md](ROBOT_LIFECYCLE.md#deterministic-replay-roadmap-phase-205--world-clock)); the work loop's `job`, `activity`, `stationId`, `siteId` and `position`, and its site cooldowns and timelines (live visual state on wall-clock time: not replayable, and a restored world's work loop starts fresh from each robot's `docking`, Roadmap Phase 43); `audioMode` (solo/mute); `masterVolume`; and all UI/layout state (open accordions, selected nav tab, etc.).

**Why a manual pan and the two sends are saved and `masterVolume` and `audioMode` are not:** a manual pan is a composition choice (where a robot's voice sits in the stereo field is part of the world a session describes), and so are `reverbSend` and `delaySend` (how far into the echo a robot sits is part of the world too), while volume and solo/mute are listening choices that depend on the room and the speakers the world is being heard on.

`computeRobotAudioOverrideDiff`/`computeCompanyDiff`/`buildSessionPayload`/`applySessionPayload` (`src/utils/sessionDiff.ts`) are the pure diff core. `buildSessionPayload` compares the live roster against a seed-only baseline produced by `generateRobotRosterBaseline`/`generateCompanyRosterBaseline` (`src/systems/spawnSystem.ts`) — pure functions with no store write, extracted from the real spawn path so the baseline they produce is guaranteed to match what a fresh spawn would actually generate. `applySessionPayload` regenerates the world via `worldTransition.ts`'s existing `retransmitWorld` (never a parallel regeneration path), then overlays `globalAudio`, every robot override (merged field-by-field via `useLocaleStore.updateRobot`), every company diff, and every user-created company. Company membership is reapplied via `localeStore.assignRobotToCompany` per affected robot, never a direct `robotIds` write, so a member robot's own `companyId` never desyncs from its company's roster.

## Hard Requirement: Deterministic IDs for Anything Diffed

This only works if regenerating from the same seed reproduces the same IDs in the same order, so a persisted diff can be matched back up to the right entity. **Robot IDs** and **spawn-generated Company IDs** already satisfy this (`generateRobotId`/`generateCompanyId`, `src/systems/spawnSystem.ts`, Phase 6). **User-created Companies** are the one exception, deliberately: they have no seed to derive an id from, so they keep `crypto.randomUUID()` and persist as full objects instead of a diff (see "What Gets Persisted" above).

## The Storage Engine (`src/utils/sessionStorageEngine.ts`)

One namespaced `localStorage` key, `STORAGE_KEY = 'trace-atlas.sessions.v1'`, holding named entries only — `{ named: Record<string, SessionEntry> }`:

- `saveNamedSession(name, payload)` — overwrites the entry named `name` in place if it exists; otherwise creates a new one. The name **is** the storage key, not a separate id.
- `deleteNamedSession(name)` — removes that entry.
- `listSessions()` — every named entry, for the panel's list.
- `loadSession(name)` — looks up a payload by name; returns `undefined` if nothing matches.

Malformed or missing `localStorage` data fails soft: `listSessions()` returns `[]`, `loadSession()` returns `undefined`, never throwing into the render path. Any leftover keys from an earlier storage shape — this codebase's own now-cut autosave-history fields, or the original 6-slot scheme's `autosave`/`nextRotatingIndex` pair — are silently ignored on read, not migrated.

## No Autosave in v1

There is no automatic or background saving of any kind. An earlier iteration of this phase shipped a plain-`setInterval` autosave (first a flat 6-slot scheme, later restructured into a per-session/unsaved-bucket history) — see "Session Autosave History was scoped, built, then cut" below. Both were removed; the only way a session reaches `localStorage` is an explicit "Save Session" click.

## The UI (`SessionsPanel.tsx` / `SessionListItem.tsx`)

`SessionsPanel` holds the Session Name input (`sessionStore.currentSessionName`, prefilled by `sessionStore.ts`'s `suggestSessionName()` — the same word-list mechanism `spawnSystem.ts`'s `generateCompanyName` uses for robot/company names, so it's never blank) and a "Save Session" button above the list of named entries, sorted by `savedAt` descending. A successful save shows a `` `Saved ${name} at ${formattedDateTime}` `` confirmation banner (`formatSessionTimestamp`, `src/utils/helpers.ts` — e.g. "Sep 28, 2:14 PM"); a failed save shows a `` `${name} failed to save.` `` message instead. `SessionsPanel` re-reads `listSessions()` after every save/delete rather than subscribing to a store, since `localStorage` reads aren't reactive.

Each `SessionListItem` row always shows its own plain name and three buttons, in this order:
- **Load** — calls `applySessionPayload(entry.payload)` and sets `sessionStore.currentLoadedSessionName` to this entry's name. Always reapplies exactly what was last explicitly saved, discarding any live tweaks since — there is no "Update" button that silently overwrites an entry with live state; overwriting is done by typing the same name into the Session Name input and clicking "Save Session" again.
- **Share Session** (Phase 21) — calls `copySessionLink(entry.payload)`, i.e. shares this row's *stored* payload, not live state. See "Shareable Links (Phase 21)" below.
- **Delete** — behind an `AlertDialog` confirm (the same pattern `CompanyCrudControls.tsx` already establishes), calls `deleteNamedSession(entry.name)`.

`SessionsPanel` itself also has its own **Share Session** button next to Save Session, which shares the *current live state* (`copySessionLink(buildSessionPayload())`) instead of a stored entry — the inverse of the per-row button above.

A **"Clear Local Storage"** button (lore label "Reset to Factory Settings") sits at the bottom of the panel, behind its own `AlertDialog` confirm. On confirm it calls `localStorage.clear()` — all of `localStorage`, not scoped to the sessions key — and resets `currentLoadedSessionName` to `null`. It does not strip the URL query string or regenerate the world.

## Transmission presets and the off screen (layout rework, [Roadmap Phase 45](todo/roadmap.md))

Before power-on the screen offers a **Transmission** row (`OffScreen`, `src/components/panels/screen/screens/OffScreen.tsx`): the three presets, a divider, then the user's saved sessions (newest first), as a muted `RadioButton` ([COMPONENT_LIBRARY.md](COMPONENT_LIBRARY.md)) with a well naming the pick and its Attenuation Style code.

- **A preset is a `SessionPayload` constant.** `TRANSMISSION_PRESETS` (`src/data/transmissionPresets.ts`) is three `{ id, nameKey, payload }` entries, validated by the same checks a saved session passes. The id is stable (the picker keys its options on it); the name is a content key (`home.off.presets.*`), never a field. The three payloads and their names are **placeholders** until curated: each was captured with `buildSessionPayload()` on a freshly booted world and given its own Attenuation Style name and coordinates.
- **Picking retransmits silently.** The pick goes through `applySessionPayload`, the same path Load takes, and never touches `AudioEngine`: only the power switch starts sound. A pick that changes the coordinates rebuilds the faint world behind the screen. The saves are read once on mount (`listSessions`; nothing can add one while the power is off), and a save that has since vanished from storage (`loadSession` returns nothing) applies nothing and is not claimed as the pick.
- **The world is built before power-on and started on the rocker.** `WorldView` mounts in both power states and its mount effect builds the world with `initializeLocale(localeId, { startSystems: isPoweredOn })` — the BUILD half only (district, roster, companies). The START half, `startLocaleSystems` (the robot-lifecycle tick, the work loop, the Audio Swells tick), runs on `powerController.powerOnSequence()`, after `AudioEngine.start()` has registered every robot's voice. A powered-off retransmit passes `startSystems: false`; a powered-on one passes `true`, as before. So the faint world is a still frame: no lifecycle, no LFOs, no swells ([PERFORMANCE.md](PERFORMANCE.md) records the powered-off idle cost).

## Shareable Links (Phase 21)

`src/utils/sessionShareUtils.ts` encodes a `SessionPayload` as plain (uncompressed) UTF-8-safe base64 JSON into a single `?session=` URL query param — no new dependency, no new payload shape. `buildShareUrl` produces `origin + pathname + ?session=<encoded>`, deliberately dropping any other query params present (e.g. a stray `?debug`); `copySessionLink` writes that link to the clipboard via `navigator.clipboard.writeText`, resolving `true`/`false` (never throwing) so both Share buttons can show "Link copied" or "Unable to copy" (auto-dismissing after 5 seconds).

**Opening a link with `?session=` present loads it in two phases, to avoid a flash of the wrong world:**
1. **Before the default locale is constructed** (module-load time, synchronous): `getSessionSharePayload()` (decoded once from the URL at import) feeds the payload's exact `attenuationStyleName`/`coordinates` directly into `attenuationStyleStore.ts`'s `DEFAULT_ATTENUATION_STYLE_NAME` and `localeStore.ts`'s `DEFAULT_LOCALE_COORDINATES` — the same module-level-constant timing the old `?seed=`/`?x=`/`?y=` debug params used to use (see "Boot Behavior" below). This is deliberately **not** routed through `deriveAttenuationStyleSeed`'s override mechanism — that would both sanitize the name (lowercase, strip punctuation) and persist for the rest of the session, silently hijacking the seed of every *other* Attenuation Style created afterward.
2. **Right after `OceanScene.tsx`'s existing mount-effect `initializeLocale` call:** `applySessionPayload(sharePayload, { skipLocaleRebuild: true })` applies `robotOverrides`/`companyDiffs`/`globalAudio`/`userCreatedCompanies` on top. The `skipLocaleRebuild` option (new on `applySessionPayload`) skips its normal `retransmitWorld` call entirely — `resolveRetransmitAction` has no "already correct" short-circuit, so calling it unchanged here would tear down and rebuild the locale phase 1 already built correctly, a second time in the same boot.

**Known limitation:** a session saved while `?seed=`'s successor debug mechanism (the `setGlobalAttenuationStyleSeedOverride`/`setLocaleCoordinateOverride` primitives, still callable directly by tests/tooling — see "Boot Behavior") was active won't reproduce identically via a share link, since `SessionPayload` doesn't capture that override. Not a concern for normal save/share usage — only for a session saved under manual, direct API-level testing.

A loaded shared link behaves like a Load afterward, not a read-only preview: the Session Name input keeps its normal freshly-generated suggestion, and "Save Session" persists it locally like any other load. The URL param stays in the address bar — no clearing — so the link is durable and bookmarkable, not one-time-use. There is still no manual "paste a link" import UI; opening a URL with the param is the only way in.

## Free | Sync across a save and a share link (docs/specs/FREE_SYNC_TOGGLE.md §1.8)

A `SessionPayload` also carries `bpm` and `lfoBank` (all four lanes, whole — never diffed), beyond the field list under "What Gets Persisted", so the tempo and each lane's mode survive a save. The two tempo-syncable values add one optional field each, and nothing else changed:

- **Saved sessions** (`version` stays `2`; no migration): `lfoBank` is captured by spreading each lane, so a lane's optional `sync` note rides along; `globalAudio` is captured whole, so `delay.sync` does too. Absent anywhere means Free — a pre-Sync save loads with every toggle on Float and its own tempo.
- **Restore boundary** (`applySessionPayload`, `src/utils/sessionDiff.ts`): `sanitizeLaneSync` / `sanitizeDelaySync` drop any `sync` that isn't a real note (`isNoteValue`, `src/data/noteValues.ts`) — a hand-edited `localStorage` entry, a corrupt link — before it reaches state or the engine, so a bad value restores as Free, with no `sync` key at all. Each is applied once: the lanes after `backfillLfoBank` and before the running / not-running branch split (so both branches get clean lanes), the Delay before the store write and the engine push. They return the input untouched when there is nothing to drop and otherwise a new object, never mutating the payload. Lanes restore through `replaceLfoBankLane` when the audio context is running — a `setLfoBank` merge cannot delete a key, so a Free lane in the payload would keep the live lane's stale `sync` — and a whole `setState` when it isn't. A synced Delay reaches the node resolved at the *payload's* tempo, not the live world's tempo a moment earlier.
- **Share links** (`src/utils/sessionShareUtils.ts`): each wire lane entry gains an optional `y`, a compact note code — a division token (`32`, `16`, `8`, `4`, `2`, `1b`, `2b`, `4b`) plus a modifier suffix (none / `d` dotted / `t` triplet): `4` a quarter, `8d` a dotted eighth, `16t` a sixteenth triplet, `1b` one bar. Decoding is a code → note `Map` built once from `NOTE_VALUES` (`NOTE_VALUE_BY_CODE`), so exactly the 20 real codes decode; anything else — an unknown token, a modifier the division doesn't offer (`2bd`: 2 bars are straight-only), wrong case, padding, a non-string, `__proto__` — leaves the lane Free. The encoder writes a code only for a valid note, so a Free lane's wire entry is byte-for-byte what it was before Sync existed. The Delay needs no codec of its own: `delay.sync` travels inside `g` (the whole `globalAudio`), and the restore-boundary sanitiser covers a malformed one.

## Robot Pan across a save and a share link (docs/specs/ROBOT_PAN.md §1.6)

`RobotAudioOverrideDiff` gains one optional `pan` (−1…1). **Present means Auto off at that value; absent means Auto**, the baseline every robot spawns with, so there is no `panAuto` key and `RobotAudioBaseline` gained no field. An untouched robot adds nothing to `robotOverrides`, and an Auto robot never writes a key even if its stored `pan` is stale.

- **Diff** (`computeRobotAudioOverrideDiff`): `pan` is written only when `panAuto === false` (a robot with no flag is Auto, not manual), rounded to two decimals, the slider's 1/100 step. A manual pan of exactly `0` is still written.
- **Restore** (`buildRobotUpdates`): the one key sets both robot fields, `pan` and `panAuto: false`. A non-finite `pan` (a hand-edited payload) is ignored whole and the robot stays Auto; an out-of-range one is clamped by `localeStore.updateRobot`. The apply loop then calls `AudioEngine.updateRobotPan` with the **stored**, clamped value, only for a diff that made the robot manual. Before the audio context starts that is a no-op, and `loadInstruments`' post-load reservation pass re-primes from the store.
- **Share links** (`sessionShareUtils.ts`): `CompactRobotOverrideDiff.p`, beside `pr`. The decoder keeps `p` only when it is a finite number in `[PAN_MIN, PAN_MAX]`; anything else is dropped, so a tampered or truncated link leaves the robot on Auto and is never misread as a manual pan. The payload `version` stays 2: an absent key is Auto, which older links already mean.

## Robot Articulation across a save and a share link (docs/specs/ROBOT_ARTICULATION.md §1.7)

`RobotAudioOverrideDiff` gains three optional fields, `portamento`, `filterQ` and `filterType`, and the envelope's two curves travel inside the existing whole-object `adsr`. The bus link (`bus.frequency`) needs nothing new: it is one more target in the existing per-target `lfoLinks` diff.

- **Diff** (`computeRobotAudioOverrideDiff`): each of the three is compared with `deepEqual` against the baseline, which `generateRobotAudioBaseline` seeds through the same function as spawn, so an untouched robot still diffs to `{}`. A recorded `portamento` of `0` is a real value (the seeded glide switched off), so presence is checked against `undefined`, never by truthiness.
- **Restore** (`buildRobotUpdates` and the apply loop): `validArticulation` keeps a finite number for `portamento` and `filterQ` and a listed type for `filterType`; a payload `adsr` with an unlisted curve name loses just that curve key. The loop then calls `AudioEngine.updateVoicePortamento` and `AudioEngine.updateRobotBusFilter` only for a robot that is reserved. Before the audio context starts that is a no-op, and every reservation path (`loadInstruments`' post-load pass, `reReserveVoice`) re-reads the store, so the engine ends up primed either way. A payload without the keys leaves the fields absent, which means no glide, Q 1 and lowpass.
- **Share links** (`sessionShareUtils.ts`): `CompactRobotOverrideDiff.po`, `fq` and `ft`, and `CompactADSR.ac` / `rc` (written only when the curve is present). Decoding validates each key on its own: a non-finite or non-numeric `po` / `fq`, an `ft` that is not `lowpass`, `bandpass` or `highpass`, and an `ac` / `rc` that is not one of the seven curve names are all dropped, so a tampered link leaves that one field at its default. The payload `version` stays 2: an absent key already means the default.

## Robot Sends across a save and a share link (docs/specs/ROBOT_SENDS.md §1.7)

`RobotAudioOverrideDiff` gains two optional fields, `reverbSend` and `delaySend` (0…1, two decimals). **Present means that send differs from the robot's seeded one; absent means the seeded value**, which `generateRobotAudioBaseline` reproduces through the same `generateRobotSends` as spawn (the baseline gained both fields). A send of exactly `0` is a real value (a robot moved to fully dry), so presence is checked against `undefined`, never by truthiness. The two Fleet Params return levels (`globalAudio.reverb.wet` / `delay.wet`) persist as they always did; their meaning is now "return level", their seeded baseline is `1`, and the payload shape did not change.

- **Diff** (`computeRobotAudioOverrideDiff`): the live and the seeded send are both rounded to two decimals, the slider's 1/100 step and the seed's quantization, before comparing, so float noise or a seed off the grid never reads as a change and an untouched robot still diffs to `{}`. A session saved mid-swell stores the swell's **base** (`extractSwellBaseValueIfActive`), never the interpolated value. A live robot with no send at all (an older save) writes no key.
- **Restore** (`buildRobotUpdates` and the apply loop): each send is kept only when it is a number inside `[SEND_MIN, SEND_MAX]`, key by key, so one bad send never costs the other or any field beside it; `NaN`, the infinities and out-of-range values all fall out of that one range test. The loop then calls `AudioEngine.updateRobotSends` with the **stored** value (already in range), and only for the sends the diff carried. Before the audio context starts that is a no-op and every reservation path re-primes from the store; on a full-rebuild restore the reservation pass primes both seeded sends first and the restore's prime lands last.
- **Share links** (`sessionShareUtils.ts`): `CompactRobotOverrideDiff.rs` and `ds`, beside `p`. The decoder keeps each only when it is a number in `[SEND_MIN, SEND_MAX]`; a string, `null` (what JSON makes of a `NaN`), a boolean or an out-of-range value is dropped on its own, so a tampered link leaves the robot at its seeded send. The payload `version` stays 2: an absent key already means the seeded value. A link made before the sends existed decodes to exactly the diff it always did.
- **Companies** are not persisted as a snapshot (`companyDiffs` carries only `name` and membership), so a company move is saved as the per-robot sends it left behind.

## Robot Performance across a save and a share link (docs/specs/ROBOT_PERFORMANCE.md §1.7)

`RobotAudioOverrideDiff` gains three optional fields, `dynamics`, `rests` and `accents` (0…100 integers, as on `Robot`), and `SessionPayload` gains `humanize` (ms, `audioStore.humanize`). **Present means the value differs from the seeded one; absent means the seeded value**, which `generateRobotAudioBaseline` reproduces (the baseline carries all three). A `0` is a real value (a robot flattened to no dynamics, no rests or no accents), so presence is checked against `undefined`, never by truthiness. The payload `version` stays 2.

- **Diff** (`computeRobotAudioOverrideDiff`): each field diffs like `pitchRepeat`, key by key, so a robot edited to `dynamics 70 / rests 30 / accents 60` writes exactly those three keys and an untouched robot writes `{}`. A live robot with no value for a field (an older save) writes no key.
- **Restore** (`buildRobotUpdates` and the apply loop): each field is kept only when it is a finite number, key by key, so `rests: NaN` or `accents: 'x'` is dropped whole without costing the keys beside it; `updateRobot` clamps the range. Nothing new is primed: the loop's existing `regenerateMelody` call re-stamps the restored `rests` / `accents` into the melody from the stored robot, so the registered melody after a restore equals a fresh regeneration with those values. Dynamics is read by the engine on every note and needs no push.
- **Humanize** is captured beside `swellDuration` and restored through `audioStore.setHumanize`, which clamps and pushes `AudioEngine.setHumanize`, the one path to the playback loop. An absent key leaves the current (seeded or carried-forward) value untouched, with nothing pushed.
- **Share links** (`sessionShareUtils.ts`): `CompactRobotOverrideDiff.dy` / `rt` / `ax` beside `rs` / `ds`, and the top-level `hm` beside `sd`. The decoder keeps each robot key only when it is a finite number; a string, `null` (what JSON makes of a `NaN`), a boolean or an object is dropped on its own. A non-numeric `hm` fails validation the way a non-numeric `sd` does (the whole link is rejected as malformed). A link made before the fields existed decodes to exactly the diff it always did.
- **Companies** are not persisted as a snapshot (`companyDiffs` carries only `name` and membership), so a company edit is saved as the per-robot values it left behind.

## Global Colour across a save and a share link (docs/specs/GLOBAL_COLOUR.md §1.7)

`globalAudio` gains three blocks, `distortion`, `chebyshev` and `bitCrusher`, which carry six fields: `distortion.amount`, `distortion.wet`, `chebyshev.order`, `chebyshev.wet`, `bitCrusher.bits` and `bitCrusher.wet`. They travel **whole inside `globalAudio`** like every other global field, so **nothing new is encoded**: the payload `version` stays 2, no share-link key is added, and `isValidCompactSessionPayload` still checks only that `g` is an object. The stored Mix (`wet`) is the slider position; the squaring that makes it gentle happens at the node, never in the payload.

- **A payload without the blocks loads them dry.** A session saved, or a link written, before the colour blocks existed has no such keys. `applySessionPayload` (`sessionDiff.ts`) and `fromCompactSessionPayload` (`sessionShareUtils.ts`) pass `globalAudio` through `withGlobalAudioDefaults` (`types/globalAudio.ts`), which fills any missing effect block from `DEFAULT_GLOBAL_AUDIO_SETTINGS` (Mix 0, `amount` 0.3, `order` 2, `bits` 8) and drops keys it does not know. So the recorded 50.2 baseline link decodes with all three effects off, and an old save can no longer crash the engine push on a missing block. An empty `globalAudio` used to throw (`'sync' in undefined` in the Delay sanitiser) and now restores as a full set of defaults.
- **Present blocks are kept whole.** A block that is present is never deep-merged (a `bitCrusher` of `{ wet: 0.5 }` stays without `bits`, the same whole-block convention as every other global block); `null` counts as missing; the defaults are copies, never the shared constants.
- **A fresh world's 0.25 ceiling does not apply to a restore.** No seeded Mix exceeds 0.25 on load (`COLOUR_LOAD_MIX_MAX`), but a saved or shared value restores exactly as it was hand-set, so a loud colour round-trips through save, reload and share link.
- **Presets.** The three transmission presets carry the blocks at the defaults (dry).

## Global Modulation across a save and a share link (docs/specs/GLOBAL_MODULATION_COLOUR.md §1.8)

`globalAudio` gains two more blocks, `autoWah` and `phaser`, which carry thirteen fields (seven and six; the Phaser's optional `phaser.sync` is a fourteenth key, present only while its Rate is synced). They travel **whole inside `globalAudio`**, so **nothing new is encoded**: the payload `version` stays 2, no share-link key is added, and `isValidCompactSessionPayload` stays shallow. The stored Mix (`wet`) is the slider position; the squaring happens at the node.

- **A payload without the blocks loads them dry.** A session saved, or a link written, before the pedals existed has no `autoWah` or `phaser` key. `withGlobalAudioDefaults` fills each missing block from `DEFAULT_GLOBAL_AUDIO_SETTINGS` (Mix 0) at both call sites (`applySessionPayload`, `fromCompactSessionPayload`), so the recorded 50.2 baseline link decodes with both pedals off and `applyGlobalAudioToEngine` receives full blocks.
- **An invalid `phaser.sync` is dropped.** `applySessionPayload` passes the Phaser through the same sanitiser as the Delay's `sync` (`sanitizeSyncedRate` since Global Pedals, which applies it to every synced Rate block; it was `sanitizePhaserSync`): a value that is not a note value is **deleted**, never written as `undefined`, so a corrupt save or link restores the Phaser as Free with its `rate` kept. A valid `phaser.sync` (for example `{ division: '1/2', modifier: 'straight' }`) round-trips through save and link unchanged.
- **A fresh world's seed bands do not apply to a restore.** The pedals' own Mix bands (0.2–0.5 and 0.15–0.4) govern a fresh world only; a saved or shared value restores exactly as it was hand-set.
- **Presets.** The three transmission presets carry both blocks at the defaults (dry).

## Global Pedals across a save and a share link (docs/specs/GLOBAL_PEDALS.md §1.8)

`globalAudio` gains five more blocks: `chorus`, `tremolo`, `vibrato`, `frequencyShifter` and `stereoWidener`, sixteen fields in all, plus an optional `sync` note value on each of the three LFO pedals while its Rate is synced. They travel **whole inside `globalAudio`**, so **nothing new is encoded**: the payload `version` stays 2, no share-link key is added, and `isValidCompactSessionPayload` stays shallow. The stored Mix (`wet`) is the slider position; the squaring happens at the bypass cell. Width is stored as set (0.5 is unity).

- **A payload without the blocks loads them at the defaults.** A session saved, or a link written, before the pedals existed has none of the five keys. `withGlobalAudioDefaults` fills each from `DEFAULT_GLOBAL_AUDIO_SETTINGS` (every Mix 0, Width 0.5) at both call sites, so a 50.2 or 50.4 link decodes with the new pedals dark and Width at unity.
- **A block of the wrong kind counts as missing.** `withGlobalAudioDefaults` keeps a block only if it is the same kind as its default (an object for an effect block, a boolean for `compressorBeforeDelay`), so a crafted link with `g.chorus: 1` restores the default Chorus instead of throwing in the sanitiser below. This also closed the same gap for the Phaser and the Delay, which `main` had before Global Pedals.
- **An invalid `sync` is dropped on every synced Rate block.** `applySessionPayload` runs `sanitizeSyncedRate` over each key of `SYNCED_RATE_KEYS` (`phaser`, `chorus`, `tremolo`, `vibrato`): a value that is not a note value is **deleted**, never written as `undefined`, and the pedal restores as Free with its `rate` kept. Each block is sanitised on its own; a clean block is kept as the very same object. A valid `sync` round-trips through save and link unchanged.
- **A fresh world's seed bands do not apply to a restore.** The lit bands and the two-pedal cap govern a fresh world only; a saved or shared world restores every pedal exactly as it was set, any number of them lit.
- **Presets.** The three transmission presets carry the five blocks at the defaults.

## Boot Behavior

**No session is ever auto-loaded from local storage** on refresh or a fresh tab — that's still a deliberate click ("Load"). The one boot-time exception is a shareable link's `?session=` param (Phase 21, above), which auto-loads by design — that's the whole point of a share link. `?seed=`/`?x=`/`?y=` — the old debug-only reproducibility params — were **removed** as part of shipping Phase 21: `?session=` is a strictly better version of the same idea (exact reproduction, not just a pinned seed/coordinate pair), and keeping both risked exactly the override-leak problem described above. The underlying `setGlobalAttenuationStyleSeedOverride`/`getGlobalAttenuationStyleSeedOverride`/`setLocaleCoordinateOverride`/`getLocaleCoordinateOverride` primitives (`src/utils/seedUtils.ts`) still exist and are still used by tests, `AudioDebugHud.tsx` (read-only display), and `getSeededVal.ts`/`noiseMaps.ts` — only their URL-param entry point is gone.

## Session Autosave History was scoped, built, then cut

A follow-on amendment to this phase (`docs/intent/archive/session-autosave-history.md`, `docs/specs/archive/SESSION_AUTOSAVE_HISTORY.md`, `docs/tasks/archive/SESSION_AUTOSAVE_HISTORY.md` — all marked `Status: cut. Do not implement.`) replaced the original 6-slot autosave with a per-named-session 3-deep FIFO history plus two unsaved-work buckets, a drill-down UI to browse it, and a "Primary Save" label. It was partially implemented on `features/session-updates`, then Crawford called it too complicated for a v1 and had it removed — see [docs/intent/session-autosave-removal.md](intent/session-autosave-removal.md) and [docs/specs/SESSION_AUTOSAVE_REMOVAL.md](specs/SESSION_AUTOSAVE_REMOVAL.md)/[docs/tasks/SESSION_AUTOSAVE_REMOVAL.md](tasks/SESSION_AUTOSAVE_REMOVAL.md) for the removal itself. Net effect on what's described above: no autosave of any kind survived either the original 6-slot design or its replacement — this doc's "What it does" section and everything below it describes the current, autosave-free state, not either cut design.

## What changed from the original design

This file's original draft (pre-implementation) described a different feature: a single boot-autoloaded slot, a fixed URL → `localStorage` → procedural-fallback resolution hierarchy, native `CompressionStream`/`DecompressionStream` URL serialization for link sharing, and a `FirmwareResetModal` full-state wipe with a GSAP flash timeline. **None of that shipped.** What's described above shipped instead: multi-session, name-keyed local saves, manual only (see "Session Autosave History was scoped, built, then cut" above for the two autosave designs that were built and then both removed); a "Clear Local Storage" button that overlaps with, but is narrower than, the old `FirmwareResetModal` concept (no URL-stripping, no world regeneration, no GSAP flash); and, later (Phase 21, "Shareable Links" above), URL sharing shipped too — but as plain uncompressed base64 JSON in one param, not `CompressionStream`/`DecompressionStream`, and with no import UI beyond opening the link itself.

## Forbidden Patterns

- Don't persist full robot or spawn-generated-Company objects — persist the seed/coordinates plus an override diff, per "What Gets Persisted" above. Only user-created Companies (no seed to regenerate from) get persisted in full.
- Don't add any automatic/background saving mechanism — v1 is manual-save-only; two prior autosave designs were built and both removed, see "No Autosave in v1" above.
- Don't key a named session, or a spawn-generated robot/Company override, by anything other than name (sessions) or deterministic id (overrides) — see "Hard Requirement" above.
- Don't add a compression dependency or `CompressionStream`/`DecompressionStream` for the share link — plain base64 JSON, confirmed in interview, no exceptions without a fresh decision.
- Don't build a destructive confirm as a plain `window.confirm()` — use the established `AlertDialog` pattern, as both Delete and Clear Local Storage do.
- Don't reimplement world regeneration in `sessionDiff.ts` — always route through `worldTransition.ts`'s `retransmitWorld`, except the shareable-link boot path's deliberate `skipLocaleRebuild: true` (see "Shareable Links" above) — that's an explicit, narrow opt-out, not a second regeneration path.
- Don't write company membership as a direct `robotIds` mutation — always go through `localeStore.assignRobotToCompany` so member robots' own `companyId` stays in sync.
- Don't reintroduce `?seed=`/`?x=`/`?y=` URL-param reading, or route the share link's Attenuation Style name through `deriveAttenuationStyleSeed`'s override mechanism — both were deliberately removed/avoided (see "Boot Behavior"/"Shareable Links" above); the override is global and persistent, and would sanitize the name and leak into unrelated later-created Attenuation Styles.
- Don't add a manual "paste a link or payload" import UI — the only import path is opening a URL with `?session=` present, confirmed in interview.
