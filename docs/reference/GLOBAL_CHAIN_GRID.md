# Audio Effects Label Mapping

**Global chain order — the dry chain, identical in both Decay Modes:** entry cut → EQ (3-band) → Low-Pass Filter → High-Pass Filter → filter cut → Distortion → Chebyshev → BitCrusher → AutoWah → Phaser → Chorus → Tremolo → Vibrato → FrequencyShifter → Compressor → StereoWidener → Limiter → Destination ⁵. Each of the ten effects (the nine from Distortion to FrequencyShifter, and the StereoWidener) sits in its own **bypass cell** (roadmap 50.6, the Dark-Effect Bypass): a dark effect (Mix exactly 0; for the StereoWidener, Width exactly 0.5) is disconnected from its cell and out of the signal path, and the cell passes its input dry. The two cuts are zero-delay `Delay` nodes that bound Tone's cycle search and pass the sound unchanged (`docs/AUDIO_SYSTEM.md`, "The bypass cells"); every cell ends in one too. **Delay and Reverb are not stages in it** (Robot Sends, roadmap 50.2): they are two shared rooms beside it, each fed by every robot's own send gain and followed by a return gain, and the Delay and Reverb `wet` rows below set those return gains (see `docs/AUDIO_SYSTEM.md`'s Signal Graph).

**"Natural Decay" (default):** both returns rejoin the dry chain at the Compressor's input.

**"Controlled Decay"** (user toggle, `compressorBeforeDelay: true`): the same dry chain, but both returns rejoin it at the StereoWidener cell's input, lit or dark, just before the Limiter, so the echoes skip the Compressor but still pass through Width (footnote ⁵; the Limiter's input before Global Pedals, and still the fallback when no Width cell exists). (The in-app Decay Mode copy says the same; it was corrected to this wiring after Robot Sends — see `docs/AUDIO_SYSTEM.md`.) Robot voice busses always connect in at the entry cut, which feeds EQ (3-band) — first in both topologies — and tap their sends off the bus filter, ahead of it.

**This table is the source of truth for both ranges every field carries:**
- **Unit / Range** — the full range: what the UI slider exposes and what the app itself supports. Verified directly against Tone.js v15.1.22's own source (`@min`/`@max` doc comments where Tone documents them; its own reference-range prose where it doesn't) — see the notes at the bottom.
- **Loading Range** — a narrower sub-range of the above, the only window a *fresh seed* is allowed to land a value in. Never presented in the UI, never a cap on what the app can do — purely bounds what `generateGlobalAudioSettings` rolls at planet-load time. Confirmed with the user per-effect; `src/data/globalAudioLoadingRanges.ts` is a direct, mechanical transcription of this column, not an independent source (except the two `wet` rows, which now describe the per-robot send bands — footnote ² below).
- **LFO?** — whether this field is one of the 7 `GlobalLfoTargetId`s (`src/types/lfo.ts`) that can carry an inline `LfoLink` (Lane + Depth, `src/components/ui/controls/LfoLink.tsx`), rendered directly beneath the field's own slider. There is no per-field shape/rate any more — a linked field's oscillator is whichever of the 4 shared LFO Bank lanes its own `LfoLink` picks (`docs/specs/LFO_BANK.md`, `docs/AUDIO_SYSTEM.md`'s LFO Modulation section); Rate/Shape/Rate Drift/Depth Drift bounds live on the lane, in the **Master / Chain-Level Controls** section below, not per row here. A field's own `LfoLink` can pick any of the 4 lanes, same as every robot field — there is no fixed per-effect-block assignment the way the old 4-group Drift design had (see that section's own note on what replaced it).
- **Swell?** — whether this field is one of the 7 `SwellGlobalTargetId`s (the same 7 as the LFO column; `delay.wet` and `reverb.wet` left the pool with Robot Sends, and the swells moved to each robot's sends) (`src/types/audioSwell.ts`) the Audio Swells system can pick as a global-pool target for a rare, self-reversing ramp. Per-swell magnitude/duration are drawn dynamically, not fixed per field — see `docs/specs/AUDIO_SWELLS.md`. Both pools (this one, and the separate 19-attribute robot pool) are governed session-wide by one master control — see **Ping Variance Automation** in the Master Controls section below.

¹ **Delay Time has a Free \| Sync mode** (`docs/specs/FREE_SYNC_TOGGLE.md`): Free is the plain seconds slider above; Sync (shown to the user as "Anchored") steps through note values of the tempo instead, and the stored note resolves to seconds at the current tempo (`resolveDelayTimeSeconds`, `src/utils/tempoSync.ts`), clamped into `DELAY_TIME_RANGE_SECONDS` (`src/types/globalAudio.ts`, `0–10` s). `DelaySettings.sync?` is optional — absent means Free. Roughly two in three fresh Attenuation Styles seed Delay Anchored (`DELAY_SYNC_ODDS`, `globalAudioSeed.ts`), with the note drawn from the `0.05–0.5` s loading range at the style's tempo; the Free `delayTime` is still seeded as before and kept underneath. See `docs/AUDIO_SYSTEM.md`'s "Free | Sync" section.

² **Delay and Reverb `wet` are return levels, not mixes** (Robot Sends, `docs/specs/ROBOT_SENDS.md` §1.3). The Tone nodes themselves are permanently `wet: 1`; the setting drives the room's return gain, so it is how loud the whole room is as heard from every robot, and `0` silences the room. It is no longer seeded (`generateGlobalAudioSettings` sets both to `DEFAULT_GLOBAL_AUDIO_SETTINGS.*.wet`, `1`; the `globalAudio.delay.quiet` draw is gone) and no longer a swell target. The two old Loading Range bands (Delay `0–0.3`, Reverb `0.1–0.6`, widened from `0.1–0.4` by the Classic Band Retune, 2026-10-21, for more contrast between a dry robot and a wet one) survive in `src/data/globalAudioLoadingRanges.ts` with a comment saying so: they are the **per-robot send bands** now (`generateRobotSends` seeds each robot's `reverbSend` and `delaySend` from them, Delay with a roll that puts exactly `0` on a share of the fleet). The sampled values this column once described no longer exist; a `?session=` payload that carries a smaller `wet` simply loads that return level.

³ **Colour (`distortion`, `chebyshev`, `bitCrusher`) sits on the dry chain between the High-Pass Filter and the Compressor: one node each, nothing per robot, and none is an LFO or swell target** (Global Colour, roadmap 50.3; `docs/specs/GLOBAL_COLOUR.md`). The Mix (`wet`) is stored as the slider position and reaches the effect **squared** (`colourWetGain`; since roadmap 50.6 it sets the effect's bypass cell rather than the node's own `wet`), so the Unit / Range and Loading Range columns for these rows are slider positions, not node `wet` values. A fresh world draws one character (`COLOUR_CHARACTER_BANDS`): clean, or exactly one of the three effects, about 25 % each. The lit effect's Mix lands in its Loading Range, and the other two seed Mix 0 while still drawing their shape value (`amount`, `order`, `bits`) from their own band. No seeded Mix is above 0.25 (`COLOUR_LOAD_MIX_MAX`); all three seed from one shared band, 0.1–0.2, a wet layer of −36 dB at the floor and −24 dB at the ceiling (a squared slider: −48 dB at 0.05, −14 dB at 0.35). The Classic Band Retune (2026-10-21) first raised the ceiling to 0.35 with bands of 0.2–0.35, and Crawford's listen the same day found them far too strong ("much more subtle"); a saved session or share link restores what was hand-set. The Effect Label and Param Label columns for these rows are placeholders for the copy pass; the shipped copy is in `src/content/copy/fleet.ts`.

⁴ **Modulation (`autoWah`, `phaser`) sits on the dry chain between Colour and the Compressor, wah first: one node each, nothing per robot, and neither is an LFO or swell target** (Global Modulation, roadmap 50.4; `docs/specs/GLOBAL_MODULATION_COLOUR.md`). Every parameter of each Tone node is a slider. The Mix (`wet`) is a slider position squared (`colourWetGain`), as for Colour, at the pedal's bypass cell since roadmap 50.6, and its seeded band is the pedal's own, above Colour's ceiling (`COLOUR_LOAD_MIX_MAX`, 0.25, which still holds for the colour effects): 0.35–0.5 for the AutoWah, 0.3–0.4 for the Phaser (the ceilings are Crawford's, from the roadmap 50.4 T16 listen, where his recommended 0.3–0.7 and 0.25–0.6 were brought down by a third; the floors rose at the Classic Band Retune, 2026-10-21, because the bottom third of a squared slider is near silence: the wet layer is about −14 dB at 0.35 and −17 dB at 0.3, against −29 dB at 0.15). The AutoWah's sensitivity band is −20 to −5 dB, since Tone boosts the follower by −sensitivity dB and at −40 on a fleet near 0 dBFS the filter sits open and never sweeps. Each pedal is lit in about a third of fresh worlds, independently of the other and of Colour's character draw (`PEDAL_LIT_EDGE`); a dark pedal seeds Mix 0 and still draws every other field from its band. The Phaser's Rate is the third Free \| Sync field (`PhaserSettings.sync?`, `resolveSyncedRateHz`, `src/utils/tempoSync.ts`); about half of lit Phasers seed Sync (`PEDAL_SYNC_ODDS.phaser`). `stages` is constructor-only in Tone, so changing it rebuilds the node. The Effect Label and Param Label columns are placeholders for the copy pass.

⁵ **Global Pedals (`chorus`, `tremolo`, `vibrato`, `frequencyShifter`, `stereoWidener`; roadmap 50.6, `docs/specs/GLOBAL_PEDALS.md`).** The four motion pedals sit on the dry chain after the Phaser and before the Compressor, in that order, so the rooms' returns rejoin after them in both Decay Modes; every one keeps left and right apart except the shifter, whose sine branch is downmixed to mono (it enters an AudioParam), so a panned voice leaks the shifter's other sideband and a copy into the far channel (measured, spec §8). The widener (Width) sits between the Compressor and the Limiter: under Controlled Decay the returns join at its input instead of the Limiter's, so it hears the rooms in both modes and Width 0 folds everything to mono. One node each, nothing per robot, none an LFO or swell target. Each Mix (`wet`) is a slider position squared at the pedal's bypass cell (`colourWetGain`); Width is never tapered (0.5 is unity, and exactly 0.5 is the widener's dark state). The three LFO rates (`rate`, Tone's `frequency`) are Free \| Sync fields on the generic rail (`resolveSyncedRateHz`) over the Phaser's range, `PEDAL_RATE_RANGE_HZ`; the shift is signed, and a fresh world seeds it as a ±(2–20) Hz magnitude band with the sign drawn separately. Each motion pedal rolls its own lit edge (`PEDAL_LIT_EDGE`), in chain order after the AutoWah and Phaser rolls, and is forced dark once two Modulation pedals are lit (`MAX_LIT_PEDALS`); a dark pedal seeds Mix 0 and still draws its other fields. A lit LFO pedal seeds Sync under its own entry of `PEDAL_SYNC_ODDS`: about three quarters of lit Tremolos (a Free tremolo beats against the 16th grid; Classic Band Retune, 2026-10-21) and about half of lit Chorus and Vibrato worlds (measured 75.14 %, 49.82 % and 49.73 % over 20 000 styles). The widener has no lit roll: every fresh world seeds it 0.4–0.65, and about 4 % of worlds land on exactly 0.5, unity, where its cell is dark (4.36 % of 5 000 styles, measured 2026-10-21). Crawford's listen (T16, 2026-10-20) kept every Loading Range band as built, the shifter's ±(2–20) Hz included; the Effect / Param labels are placeholders for the copy pass.

## Master / Chain-Level Controls (not per-effect-param)

These govern the whole chain, a whole LFO Bank lane, or both swell pools at once — none of them are a field on one `AudioRigEffectKey` block, so none get a row in the table above. `Decay Mode` and the 4 LFO Bank lanes are shipped (`src/data/audioRigConfig.ts`'s `DECAY_MODE_SCHEMA`/`LFO_BANK_LANE_SCHEMAS` + `AudioRigDrawer.tsx`, rendered as the bare `master-row` above the effect blocks plus the Fleet Params → LFO Bank accordion — see `docs/AUDIO_SYSTEM.md`'s LFO Modulation section). **Ping Variance Automation is not yet shipped** — see the status note beneath the table.

There is no rig-wide bypass control and no per-effect Enabled toggle — both were removed; every effect's "off" state is now expressed purely through its own params (wet=0, a filter's own passthrough frequency, etc.).

**The 4 LFO Bank lanes replaced the old 4-group Drift design** (`docs/tasks/LFO_BANK.md`, 2026-10-01) — `EQ Drift`/`Low-Pass Drift`/`High-Pass Drift`/`Robot Drift` and their per-group `rateDrift`/`depthDrift` pairs are gone; a field no longer belongs to a fixed drift group at all. Instead, any field's own `LfoLink` (this table's `LFO?` column, or `docs/reference/ROBOT_DATA_GRID.md`'s `Has LFO` column for robot fields) picks one of 4 shared lanes, and that lane's own Rate Drift/Depth Drift — set once per lane, below — rides along automatically for every field linked to it:

## Notes from the Tone.js verification pass (V2)

- **Compressor** — every full-range value above checked exactly against `Tone.Compressor`'s own `@min`/`@max` doc comments: `ratio` (1–20) and `knee` (0–40) match Tone's hard bounds exactly; `threshold` (−60 to 0) is a deliberately narrower slice of Tone's true −100 to 0; `attack` (0.001–0.2) and `release` (0.01–1) both sit safely inside Tone's 0–1.
- **Low-Pass/High-Pass Filter** frequency (20–20000 Hz) isn't just a UI convention — it's the exact range `Tone.Filter`'s own class doc references ("frequency response curve... between 20hz-20khz"). `Q` has no Tone-documented bound; 0.1–20 is a conventional musically-useful range, not derived from a hard limit.
- **EQ (3-band)** `low`/`mid`/`high` have no Tone-documented numeric bound either; ±12 dB full range is a conventional EQ range, a judgment call not a hard constraint. `Tone.EQ3` also exposes a shared `Q` and `lowFrequency`/`highFrequency` crossover points that aren't surfaced as controls here — noted, not added.
- **Delay** `feedback` is capped at 0.95, short of Tone's technical 0–1, to avoid runaway buildup near unity. `delayTime`'s 0–10s full range matches the explicit `maxDelay: 10` set on the underlying `Tone.FeedbackDelay` node (`globalFx.ts`) — the two must stay in sync, which is why the range is the shared `DELAY_TIME_RANGE_SECONDS` constant (`src/types/globalAudio.ts`) with a comment on the node pointing back at it. (This grid used to say 0–1 s / `maxDelay: 1`; that was stale — the node's real cap was 10 s.) LFO judged unwanted on Delay's own time parameter, hence no `LFO?` flag; `delay.wet` never got one either, but is still swell-eligible (Audio Swells was built independently of LFO/Drift, per `docs/specs/AUDIO_SWELLS.md` §1.1 — it deliberately reuses neither `Tone.LFO` nor a Signal/Param connection).
- **Reverb** — `Tone.Reverb` (v15.1.22) has no `dampening` property; Reverb has exactly 3 real params (`decay`/`preDelay`/`wet`). `decay`/`preDelay` full ranges have no Tone-documented caps; the existing ranges are conventional, not corrected.
- **Limiter** — `Tone.Limiter` exposes exactly one param, `threshold` (default −12 dB), internally wrapping a `Compressor` with a fixed `ratio: 20`/`attack: 0.003`/`release: 0.01` (none adjustable). The −20 to 0 dB full range is a proposed convention (a limiter's threshold conventionally stays near the ceiling, unlike a general compressor's much wider −100 to 0) — accepted by the user via its loading range fitting comfortably inside it; flag if that full range itself needs revisiting.
- **Loading ranges** (this table's own dedicated column) were set together with the user, per effect, after the full-range review above — see `docs/specs/AUDIO_RIG_V2.md` and `docs/tasks/AUDIO_RIG_V2.md` for how they flow into `src/data/globalAudioLoadingRanges.ts`.
- **LFO Drift's loading range** (−0.7 to 0.7, i.e. −70% to 70%) postdates the pass above and isn't a Tone.js verification concern — it's a UI-feel call. First shipped narrower (−0.4 to 0.4) and widened after a manual/audible check on `docs/tasks/LFO_DRIFT_GROUPS.md` found the seeded default read as too subtle, confirmed directly with the user (`src/data/globalAudioLoadingRanges.ts`).
